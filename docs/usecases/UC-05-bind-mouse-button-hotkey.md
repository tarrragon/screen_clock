# UC-05: 綁定按鍵快捷鍵

## 基本資訊

| 項目 | 值 |
|------|-----|
| 用例 ID | UC-05 |
| 用例名稱 | 綁定按鍵快捷鍵 |
| 主要行為者 | screen_clock 使用者（已將某滑鼠側鍵綁定為快捷鍵動作） |
| 利益關係人 | 使用者：免持鍵盤即可觸發常用快捷鍵組合 |
| 前置條件 | 已於系統設定授予「輔助使用（Accessibility）」權限；設定面板已完成一次「新增綁定」流程（偵測捕捉側鍵 -> 選擇快捷鍵動作 -> 於聚焦狀態擷取鍵盤組合鍵）並儲存；app 啟動時已將綁定清單下傳原生端並建立 CGEventTap |
| 成功保證 | 按一下綁定鍵，前景 app 收到對應的鍵盤組合鍵事件；原側鍵的系統預設動作不觸發 |

## 主要成功場景

1. **按下綁定鍵**
   - 使用者按一下已綁定為快捷鍵動作的滑鼠側鍵
   - 原生端（`handleButtonDown`）比對 buttonNumber 命中 Hotkey 綁定，呼叫 `synthesizeHotkey` 合成鍵盤事件；該次 `otherMouseDown` 事件被消費（回傳 nil），原按鍵的系統預設動作（如上一頁/下一頁）不觸發

2. **合成組合鍵事件**
   - 原生端將 `HotkeyAction.keyCode`（Flutter physicalKey 的 usbHidUsage）查表換算為 macOS CGKeyCode，modifiers 換算為 CGEventFlags
   - 依換算結果合成一組 keyDown + keyUp 事件並 post 到系統前景 session；一次按下只送一次組合鍵，不連發

3. **前景 app 接收**
   - 前景 app 收到並執行對應的鍵盤組合鍵動作（如複製、螢幕截圖）

4. **放開綁定鍵**
   - 使用者放開該側鍵
   - 原生端未將 Hotkey 綁定標記為拖曳狀態，故該次 `otherMouseUp` 事件不會被本綁定機制消費，依原樣放行；僅 DragScroll 綁定的放開事件才會被消費（見 UC-04）

## 例外場景

### EX-05-01: 未取得輔助使用授權

| 項目 | 值 |
|------|-----|
| 觸發條件 | 使用者尚未於系統設定開啟「輔助使用」授權，或授權後被使用者收回 |
| 錯誤碼 | — |
| 處理方式 | 與 UC-04 EX-04-01 相同機制：原生端判定未授權時不建立 CGEventTap，僅記錄 NSLog |
| 使用者提示 | 設定面板顯示未授權引導文字與「開啟系統授權」按鈕 |
| 恢復策略 | 授權後原生端經 onPermissionChanged 回報，Dart 端補下傳綁定並建立 tap；授權完成前按下側鍵行為等同未綁定 |

### EX-05-02: CGEventTap 建立失敗

| 項目 | 值 |
|------|-----|
| 觸發條件 | 已授權但 `CGEvent.tapCreate` 回傳 nil |
| 錯誤碼 | — |
| 處理方式 | 與 UC-04 EX-04-02 相同機制：記錄 NSLog，功能不生效，app 其餘功能不受影響 |
| 使用者提示 | 無；查無對應 UI 呈現機制，標註為未定義 |
| 恢復策略 | 查無明確主動重試機制；下一次綁定變更會使 `ensureTap` 重試 |

### EX-05-03: keyCode 無對應 CGKeyCode（合成略過）

| 項目 | 值 |
|------|-----|
| 觸發條件 | `HotkeyAction.keyCode` 為 0（容錯還原缺欄時的預設值），或對照表 `hidUsageToCGKeyCode` 未涵蓋該 usbHidUsage（如小鍵盤、多媒體鍵等非標準鍵） |
| 錯誤碼 | — |
| 處理方式 | 原生端 `synthesizeHotkey` 記錄 NSLog 警告後直接 return，不合成任何鍵盤事件；呼叫端仍消費原側鍵按下事件，不觸發系統預設動作 |
| 使用者提示 | 無；查無對應 UI 呈現機制，標註為未定義 |
| 恢復策略 | 使用者需於設定面板重新擷取一組對照表已涵蓋的按鍵（字母、數字、方向鍵、F1-F12、常用符號、Enter/Esc/Tab/Space/Backspace/Delete） |

### EX-05-04: 綁定衝突（同一按鍵重複綁定）

| 項目 | 值 |
|------|-----|
| 觸發條件 | 使用者新增綁定時選擇了已被其他動作佔用的 buttonNumber |
| 錯誤碼 | — |
| 處理方式 | 與 UC-04 EX-04-03 相同機制：`dedupeBindingsByButton` 靜默覆蓋為最後一筆 |
| 使用者提示 | 無明確提示 |
| 恢復策略 | 使用者可重新新增或刪除綁定調整 |

## 驗收條件

### 功能驗收

- [ ] 綁定側鍵按一下，前景 app 收到對應組合鍵並執行動作
- [ ] 含多個修飾鍵的組合（如 Cmd+Shift+4）能正確送出
- [ ] 按一下只送一次組合鍵，不重複
- [ ] 原側鍵的系統預設動作（如上一頁/下一頁）於按下時被消費不觸發

### 邊界條件

- [ ] keyCode 無對應 CGKeyCode 時不合成任何鍵盤事件，但仍消費原側鍵按下事件，不崩潰
- [ ] 未授權輔助使用時，按下綁定鍵不觸發任何動作，行為等同未綁定
- [ ] 同一 buttonNumber 重複綁定時僅保留最後一筆設定

## 已知限制

| 限制 | 使用者可觀察到的現象 |
|------|-------------------|
| 對照表僅涵蓋標準鍵盤按鍵 | 綁定小鍵盤、多媒體鍵等非標準鍵時快捷鍵不會實際送出，僅側鍵按下的原生動作被消費 |
| 放開事件（Hotkey 綁定）未被消費 | SPEC-007 FR-03 要求 otherMouseUp 消費，但 handleButtonUp 僅消費 DragScroll 的放開事件；Hotkey 綁定的 mouseUp 穿透至底層（當前主流 app 不因此誤觸發）。待修正：1.4.0-W1-028 |
