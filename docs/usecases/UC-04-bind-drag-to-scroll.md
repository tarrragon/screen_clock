# UC-04: 綁定拖曳滾動

## 基本資訊

| 項目 | 值 |
|------|-----|
| 用例 ID | UC-04 |
| 用例名稱 | 綁定拖曳滾動 |
| 主要行為者 | screen_clock 使用者（已將某滑鼠側鍵綁定為拖曳滾動動作） |
| 利益關係人 | 使用者：免持滾輪即可在任意前景 app 捲動內容 |
| 前置條件 | 已於系統設定授予「輔助使用（Accessibility）」權限；設定面板已完成一次「新增綁定」流程（偵測捕捉側鍵 -> 選擇拖曳滾動動作 -> 設定方向/靈敏度）並儲存；app 啟動時已將綁定清單下傳原生端並建立 CGEventTap |
| 成功保證 | 綁定鍵按住並垂直移動期間，游標下方前景 app 的內容依設定方向與靈敏度捲動；原側鍵的系統預設動作（如上一頁/下一頁）不觸發 |

## 主要成功場景

1. **按下綁定鍵**
   - 使用者按下已綁定為拖曳滾動動作的滑鼠側鍵
   - 原生端（`InputBindingBridge.handleButtonDown`）比對 buttonNumber 命中 DragScroll 綁定，記錄當下游標 Y 座標並進入拖曳狀態；該次 `otherMouseDown` 事件被消費（回傳 nil），原按鍵的系統預設動作不觸發

2. **垂直拖曳合成捲動**
   - 使用者垂直移動滑鼠（觸發 `mouseMoved` / `otherMouseDragged` 等事件）
   - 原生端以 `Δy = 當前Y − 上次Y` 為基礎，依綁定的 direction（natural 時取負、inverted 時取正）與 sensitivity 換算捲動量；換算結果為 0 時仍取最小單位，避免慢速移動無反應
   - 換算後的捲動量合成為垂直滾輪事件，注入游標下方前景 app；該次移動事件同時被消費，不驅動系統游標位移，故螢幕上的游標圖示在拖曳期間視覺上維持原位
   - 前景 app 的內容依設定方向捲動

3. **放開結束**
   - 使用者放開綁定鍵
   - 原生端於 `otherMouseUp` 判定目前處於拖曳狀態，清除拖曳狀態並消費該次放開事件，停止合成捲動事件

## 替代場景

### 04a: 拖曳期間更新綁定清單

**觸發條件**：使用者在設定面板變更了綁定清單（新增/刪除/修改其他綁定），而某筆拖曳滾動綁定的拖曳動作正在進行中

1. Dart 端 `InputBindingController.syncBindings` 下傳新的綁定快照
2. 原生端 `applyBindings` 覆寫整份綁定表；正在進行的拖曳不受影響，因為拖曳狀態保存的是按下當下擷取的動作快照，非即時查表結果
3. 回到主要成功場景步驟 3（放開後才會套用最新綁定表）

## 例外場景

### EX-04-01: 未取得輔助使用授權

| 項目 | 值 |
|------|-----|
| 觸發條件 | 使用者尚未於系統設定開啟「輔助使用」授權，或授權後被使用者收回 |
| 錯誤碼 | — |
| 處理方式 | 原生端 `applyBindings` 判定 `AXIsProcessTrusted()` 為否時不建立 CGEventTap，僅記錄 NSLog，不回傳錯誤給 Dart |
| 使用者提示 | 設定面板顯示未授權引導文字與「開啟系統授權」按鈕（既有 FR-07 呈現，非本用例新增） |
| 恢復策略 | 使用者於系統設定開啟輔助使用權限後，原生端經 onPermissionChanged 回報，Dart 端補下傳一次綁定清單並建立 tap；授權完成前按下側鍵不會觸發任何綁定動作，行為等同尚未綁定 |

### EX-04-02: CGEventTap 建立失敗

| 項目 | 值 |
|------|-----|
| 觸發條件 | 已授權但 `CGEvent.tapCreate` 回傳 nil（如系統資源限制或額外的輸入監控限制） |
| 錯誤碼 | — |
| 處理方式 | 原生端記錄 NSLog「CGEventTap 建立失敗」，eventTap 維持 nil，功能不生效；app 其餘功能（透明遮罩、選單列等）不受影響 |
| 使用者提示 | 無；查無對應 UI 呈現機制，標註為未定義 |
| 恢復策略 | 查無明確主動重試機制；下一次綁定清單變更會使 `applyBindings` 再次呼叫 `ensureTap`，變更任一綁定或重啟 app 可能使其恢復 |

### EX-04-03: 綁定衝突（同一按鍵重複綁定）

| 項目 | 值 |
|------|-----|
| 觸發條件 | 使用者新增綁定時選擇了已被其他動作佔用的 buttonNumber |
| 錯誤碼 | — |
| 處理方式 | `SettingsModel.copyWith` 寫入 bindings 時一律套用 `dedupeBindingsByButton`：同一 buttonNumber 僅保留清單中最後出現的一筆，舊綁定被靜默覆蓋，非阻擋、非錯誤提示 |
| 使用者提示 | 無明確提示；面板重新整理後綁定清單只會顯示覆蓋後的單一綁定 |
| 恢復策略 | 使用者可重新新增或刪除綁定調整 |

## 驗收條件

### 功能驗收

- [ ] 綁定側鍵按住並垂直拖動，游標下方前景 app 內容依方向捲動
- [ ] 放開後捲動立即停止，且拖曳期間原側鍵的系統預設動作不觸發
- [ ] 靈敏度調整能改變單位位移的捲動量；即使極小位移也至少產生最小單位捲動
- [ ] 拖曳期間螢幕游標圖示視覺上不隨滑鼠移動而位移（移動事件被消費）

### 邊界條件

- [ ] 未授權輔助使用時，按下綁定鍵不觸發任何動作，行為等同未綁定
- [ ] 綁定清單為空時不建立 CGEventTap，且不觸發授權提示
- [ ] 同一 buttonNumber 重複綁定時僅保留最後一筆設定

## 已知限制

| 限制 | 使用者可觀察到的現象 |
|------|-------------------|
| 只處理垂直位移 | 水平拖曳不合成任何捲動 |
| CGEventTap 建立失敗無 UI 提示 | 功能靜默不生效，僅能從系統設定重新確認授權狀態排查 |
