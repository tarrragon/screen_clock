# v1.4.0 工作日誌 — 滑鼠定位器

**版本**: v1.4.0
**codename**: cursor-locator
**狀態**: active

---

## 背景

用戶需求：多螢幕環境下經常無法立即判斷游標位於哪個螢幕，需來回移動指向裝置掃視才能找到。screen_clock 已常駐系統，適合承載此功能。

macOS 內建「搖晃滑鼠指標以尋找」僅放大游標，解決「螢幕內找不到游標」，不解決「不知道在哪個螢幕」。本版本同時處理兩層問題：邊框閃爍標示螢幕，聚光燈與波紋標示游標位置。

需求文件：[PROP-003](../../../../proposals/PROP-003-cursor-locator.md) / [SPEC-008](../../../../spec/user-experience/SPEC-008-cursor-locator.md) / [UC-06](../../../../usecases/UC-06-locate-cursor.md)

## 關鍵設計決策

完整論證見 SPEC-008「架構決策」，此處僅列結論：

| 決策 | 結論 | 理由 |
|------|------|------|
| 特效層渲染技術 | Swift `NSWindow` + `CALayer`，不經 Flutter engine | 視窗層級屬性本就必須以原生程式碼設定；逐幀動畫在 render server 執行不佔 Dart isolate；特效層無互動、無狀態、無文字 |
| 觸發機制 | 全域鍵盤熱鍵 `Cmd + Option + L`（`hotkey_manager`） | **觸控板使用者無側鍵可綁**；鍵盤熱鍵是唯一同時涵蓋滑鼠與觸控板的觸發方式 |
| 與 SPEC-007 的關係 | 完全獨立，不擴充 `MouseAction` | 同上；附帶效益是本功能不需輔助使用授權 |

### 曾評估並排除的方案

| 方案 | 排除理由 |
|------|---------|
| 擴充 SPEC-007 `MouseAction` 新增「定位游標」動作型別 | 可重用綁定架構與設定 UI，但綁定模型以實體側鍵為鍵，觸控板不滿足前提 |
| 修飾鍵 + 連點三下（`CGEventTap` 攔截並消費） | 技術上可行且觸控板通用（輕點與左鍵同為 `leftMouseDown`），但需在左鍵熱路徑維護三連擊狀態機，判定邏輯出錯會影響所有點擊操作，風險與收益不成比例 |
| Flutter multi-window 承載特效層 | Flutter 3.38.10 stable 的 macOS windowing 未實作（`_window_io.dart` 僅 Windows 分支）。此事實會隨版本失效，故決策另以不依賴版本的理由支撐 |

## 本版本的流程教訓（前置）

規劃本版本前，曾在落後遠端 101 個 commit 的本地狀態上完成一整套需求文件（PROP-002 / SPEC-007 / UC-04 編號全數與遠端衝突，且 spec 前提被推翻），全部作廢重做。

**Why**：session 啟動時未檢查 `git status` 的 ahead/behind 資訊，直接以本地 codebase 為事實基礎進行設計。

**Consequence**：三份需求文件作廢、一個 P0 驗證 ticket 多餘（遠端 1.3.0-W1-001 早已驗證 CGEventTap 四假設）、對 v1.2.1 做了基於錯誤前提的「補驗收」操作。

**Action**：session 啟動的全量清點須包含 `git status -sb` 的 ahead/behind 檢查，落後時先 fetch 同步再進行任何設計或規劃工作。此項已為 pm-role.md「Session-start 全量清點」的既有要求，本次為執行疏漏而非規則缺口。
