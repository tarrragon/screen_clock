### 問題根因

`CursorLocatorPlaybackState` 的註解自述不變式「`.idle` 等價於無 surface，`.playing` 等價於恰有一個 surface」，但 `CursorLocatorEffectController` 把 playing 期間的資料攤成六個彼此獨立的 ivar（`surface` / `duration` / `startTimestamp` / `currentScreenFrame` / `currentDisplayID` / `cancelDeadline`），其中五個為 optional 或帶預設值。不變式因此僅存在於註解，編譯器無從協助，維持一致性全靠人工同步。

四個具體症狀皆為此結構的下游：

1. `duration` ivar 純寫入 — 寫於 `startNewPlayback`（284）與 `resetExistingPlayback`（308），但 `handleFrame` 讀的是 `state` payload 解出的 `currentDuration`（334），ivar 從未被讀取。
2. `currentDisplayID` ivar 純寫入 — 寫於 287 / 315 / 393 / 418，全檔無讀取點（`frameDriver.retarget` 取的是 `entry.displayID`）。
3. `targetFallbackFrame`（382-387）服務不可達分支 — 唯一呼叫點在 378 的 `currentScreenFrame ?? targetFallbackFrame(from:)`。該行位於 `guard case .playing` 之後，而 `currentScreenFrame` 在 playing 期間必為非 nil（`startNewPlayback` 設值、`endPlayback` 才清空），故 `??` 右側型別層面不可達。
4. `surface` 五處 optional chaining（312 / 318 / 367 / 391 / 414）對「playing 期間不可能為 nil」的情形做靜默 no-op，掩蓋潛在狀態機錯誤。

另有 `currentScreenFrame` 與 `state` payload 的 `screenFrame` 同值兩存，六處手工同步（286/301/311-315/328/347-350/378/390-394/417）。

### 影響範圍

- `macos/RunnerTests/Support/CursorLocatorTestDoubles.swift`：`SpySurfaceFactory.callCount`（198/209/212，與相鄰行的 `requestedFrames.count` 恆等，兩份真相）、`ManualFrameDriver.lastEmittedTimestamp` + `advance(to:step:)`（232/254/259-265）。

根因：playing 期間資料攤成六個獨立 optional/預設值 ivar（surface/duration/
startTimestamp/currentScreenFrame/currentDisplayID/cancelDeadline），
.idle/.playing 不變式僅靠人工同步維持。改把 playing 期間狀態收進單一
private struct PlayingSession（surface 為 non-optional、
duration/elapsed/startTimestamp/screenFrame/cancelDeadline），控制器改持有
private var session: PlayingSession?。對外的 state computed property
由 session 直接推導（session == nil -> .idle，否則組出 .playing），
不再是獨立維護的第二份真相。

一併清除三個結構下游症狀：
- duration 與 currentDisplayID 兩個純寫入死欄位（grep 確認全檔無殘留
  讀寫）：duration 已由 state 透過 session 攜帶不需另存；currentDisplayID
  從未被讀取（frameDriver.retarget 用的是傳入的 entry.displayID）。
- targetFallbackFrame 與唯一呼叫點：screenFrame 現為 session 的
  non-optional 欄位，playing 期間必然有值，?? targetFallbackFrame(...)
  的不可達分支隨結構改變直接消失，方法本身一併刪除。
- surface 五處 optional chaining（surface?.xxx）：改為
  currentSession.surface.xxx 直接呼叫（handleFrame/resetExistingPlayback
  皆先 guard var currentSession = session else { return } 取出
  non-optional 值再操作，操作完寫回 session = currentSession）；
  endPlayback 用 if let currentSession = session 取代 session?.。

generation 世代序號刻意維持在 session 之外、不隨其收放：endPlayback
在 session = nil 之後仍須遞增以攔截已捕捉舊世代值的在途幀；若隨 session
一起消失會使該攔截機制失效。原檔 198-204 對「重置刻意不遞增」的理由完整
保留於重構後的註解中。

測試替身層同型清理：SpySurfaceFactory.callCount 與 requestedFrames.count
恆等（相鄰兩行各自更新），改直接用 requestedFrames.count 判斷第幾次呼叫，
移除 callCount。ManualFrameDriver.lastEmittedTimestamp 僅服務零呼叫者
advance(to:step:)（grep 確認全 RunnerTests/Runner 無呼叫點），兩者一併
移除，emit(at:) 保留為唯一送幀入口。

修改檔案：
- macos/Runner/CursorLocatorEffectWindow.swift（commit 1dd99e0）
- macos/RunnerTests/Support/CursorLocatorTestDoubles.swift（commit 0d3d317）

驗證方式：scripts/run-tests.sh（flutter test + xcodebuild test），動手前
先跑 baseline，重構後再跑一次比對通過數；另以 grep 確認四項 acceptance

### 實作策略（PM 前置規劃，執行者可依實測調整並記錄理由）

方向：把 playing 期間的欄位收進單一 private struct，控制器只持有其 optional 形式，使 optional 層級從六個降為一個、且該 optional 的語意等同 `idle` / `playing`。

```swift
private struct ActivePlayback {
  let surface: CursorLocatorSurface      // non-optional
  let generation: UInt64
  var duration: TimeInterval
  var startTimestamp: CFTimeInterval?    // 保留 optional：首幀前確實無值
  var screenFrame: NSRect
  var displayID: CGDirectDisplayID
  var cancelDeadline: () -> Void
}
private var active: ActivePlayback?
```

隨之發生的連鎖：`surface?.` 五處變 `active.surface.`（型別保證非 nil，靜默 no-op 消失）；`currentScreenFrame ?? targetFallbackFrame(...)` 變 `active.screenFrame`，`targetFallbackFrame` 失去唯一呼叫點；`duration` 與 `currentDisplayID` 若重構後仍無讀取點則一併移除，若收進 struct 後產生讀取需求則保留並在 Solution 說明。

`generation` 是否移入 struct 需執行者判斷：`endPlayback` 在 `active = nil` 之後仍要遞增世代，若 generation 隨 struct 一起消失會失去攔截在途幀的能力（見原檔 198-204 的世代設計註解，該註解明確說明重置刻意不遞增的理由）。此處若判斷錯誤，場景 17「stop 後在途幀」與重置後續幀推進兩類測試會紅燈——這是本次重構風險最高的一點。
