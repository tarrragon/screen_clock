### 重現實驗與根因調查（thyme-python-developer）

**調查方法**：(1) 全文檢索 `.claude/hooks/`、`.claude/skills/ticket/`（含 hooks 與 ticket_system 全部原始碼）比對「shell builtin」「sandbox」「builtin」關鍵字；(2) 檢查 `.claude/settings.json`（專案）與 `~/.claude/settings.json`（全域）的 permissions allow/deny 清單；(3) 以 `git worktree add` 建立獨立 worktree，透過 Bash 工具直接執行 `ticket track complete <id> --as <agent>`（含裸引數與子 shell 兩種呼叫形式）重現。

**發現 1（結構性）**：repo 內無任何檔案實作「shell builtin 樣式比對」邏輯。`.claude/hooks/` 與 `.claude/skills/ticket/` 全文搜尋「builtin」僅命中 `cli-error-feedback-hook.py` 一處，該處是處理 `cd --help` 建議語意的既有邏輯，與本案無關。`.claude/settings.json`、`~/.claude/settings.json` 的 permissions 清單無比對「complete」或任何 shell builtin 名稱的規則。

**發現 2（重現失敗）**：在 `/tmp` 下以 `git worktree add` 建立獨立 worktree，透過 Bash 工具執行 `ticket track complete <dummy-id> --as thyme-python-developer`（裸引數形式與子 shell 形式皆測），兩次執行皆正常通過 Bash 工具（無 sandbox 阻擋），僅收到 CLI 應用層本身的 `identity-guard deny`（身份不符，預期行為，非本案要修的問題）。

**發現 3（歷史紀錄不一致）**：交叉比對三個獨立回報同一問題的 ticket：
- 1.4.0-W1-015（PC-SCLK-002 首發）：診斷為「字面引數 token `complete` 被判為不安全的 shell builtin 樣式」

- 1.4.0-W1-001.5：診斷為「被 sandbox 誤判為**跨 worktree git 操作**而拒絕執行」——與前兩者機制描述不同

三次回報的具體機制描述不一致（shell builtin token vs 跨 worktree git 操作），且均無附上逐字擷取的原始阻擋訊息，僅以「PC-SCLK-002 已知誤報」帶過。這與 `.claude/rules/core/tool-output-trust-rules.md` 規則 1-3 描述的 confabulation 風險模式相符：代理人在被阻擋後，用「先驗合理推測」取代「逐字證據」記錄根因。

**發現 4（可能的真實觸發點，未證實）**：`ticket track complete` 透過 `git_utils.py:_auto_commit_ticket_md()` 於 CLI 內部以 `subprocess.run(["git", "add"/"commit", ...])` 自動 commit ticket md（非 Claude 直接呼叫 Bash 執行 git 指令，而是 Python 子行程內部呼叫）。`.claude/references/agent-authoring-guide.md`「Worktree 陷阱」章節記載即使 `permissionMode: bypassPermissions`，`.git` 仍會提示（非自動放行）；但此caveat 描述的是 Claude 直接發出的 Edit/Write/Bash 呼叫觸及 `.git` 路徑，本案的 git 呼叫是 CLI 內部子行程，命令字串本身（`ticket track complete <id> --as <agent>`）不含字面 "git"，故此 caveat 是否適用於本案未經證實。
