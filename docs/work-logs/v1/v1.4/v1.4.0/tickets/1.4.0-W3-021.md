### 修改內容

| 檔案 | 改動 |
|------|------|
| `macos/Runner/CursorLocatorEffectWindow.swift` | `CursorLocatorCompositeRenderer` 的 `attach` / `render` / `detach` 各以一次 `CATransaction` disableActions 包裹 `renderers.forEach`；新增 private `withoutImplicitAnimations(_:)`，註解說明「停用隱含動畫是繪製一幀的環境屬性」的收斂理由 |
| `macos/Runner/CursorLocatorSpotlightRenderer.swift` | 刪除 private `withoutImplicitAnimations(_:)` 及 attach/render/detach 內三處包裝 |
| `macos/Runner/CursorLocatorRippleRenderer.swift` | 刪除 `render` 內 inline 的 `begin`/`setDisableActions`/`defer commit` |
| `macos/Runner/CursorLocatorBorderFlashRenderer.swift` | 未改動（缺陷由 composite 層統一修掉，不補第四份樣板） |
| `macos/RunnerTests/CursorLocatorEffectCompositionTests.swift` | 新增 2 個測試與 3 個 helper（`makeHostedLayer` / `animatableLayers(under:)` / `assertNoImplicitAnimation`） |

三個 renderer 的繪製邏輯（曲線、幾何、顏色）與 `CursorLocatorEffectController` / `WindowCursorLocatorSurface` / `LayerHostingView` 皆未觸碰。

### 一次改動的四項效果

1. BorderFlash 的 `borderLayer.opacity` 每幀寫入不再啟動 0.25 秒隱含動畫，FR-04 的 200 ms 週期不再被低通濾波抹平。
2. 三份重複的隱含動畫停用樣板收斂為一份。
3. `detach` 語意統一：三者皆在同一個 disableActions transaction 內移除，Ripple 的「無殘留由圖層移除保證」前提成立。
4. 每幀 transaction 由 2-3 個降為 1 個；新增第四個特效時該坑不存在。

### 測試設計：可分辨性的關鍵

初版測試以裸 `CALayer` 當宿主，實測恆綠（移除 composite 的 transaction 後仍全數通過）——隱含動畫只在圖層樹已 commit 且連上實際 render context 時才生成，脫離視窗的裸圖層寫入 animatable 屬性不產生任何動畫，該版斷言為空斷言。改以 `NSWindow` 加 layer-hosted `NSView` 建構與 production 同構的宿主，並於 attach 後與每幀之間 `CATransaction.flush()` 提交圖層樹，測試才具備分辨能力（RED 驗證見 Test Results）。視窗不 `orderFront`（實測不需要），測試期間無畫面彈出。
