### 問題根因

`SettingsModel.fromJson` 對 `cursorLocatorEffectDurationSeconds` 僅做型別轉換
（`_asDouble`），未對 SPEC-008 FR-06 定義的 0.5-3.0 秒值域做任何約束；
`AppCursorLocator.minDurationSeconds` / `maxDurationSeconds` 兩常數自
1.4.0-W1-001 建立以來零引用。越界值（含 NaN / Infinity）可從損毀的
persisted JSON 或未來輸入路徑直接進入模型，經 W2-006 的
`(value.cursorLocatorEffectDurationSeconds * 1000).round()` 換算後送入原生層。

### 影響範圍

`lib/models/settings_model.dart`（`fromJson` 解析路徑）；
`test/models/settings_model_test.dart`（新增值域夾制測試群組）。
不影響 `copyWith`／建構子直接呼叫路徑——此職責依 domain-map 屬
CursorLocatorDomain read-model（外部輸入解析）範圍，內部呼叫端
（W4 設定面板）另由 UI 層邊界控制，非本票範圍。

### 修復方式

於 `SettingsModel.fromJson` 新增私有解析函式 `_asClampedDuration(value,
fallback)`，取代原本單純的 `_asDouble(...) ?? default`：

1. 先以既有 `_asDouble` 做型別轉換（型別不符 → 落回預設，行為不變）
2. 轉換成功後檢查 `isFinite`：NaN / Infinity 一律落回 `fallback`
   （= 呼叫端傳入的 `d.cursorLocatorEffectDurationSeconds`），並以
   `developer.log`（`name: 'settings-model'`, `level: 900`）記錄，符合
   `.claude/rules/core/observability-rules.md` 規則 1（catch/防禦分支須
   有日誌）
3. 有限值以 `num.clamp(min, max).toDouble()` 夾制於
   `AppCursorLocator.minDurationSeconds` ～ `maxDurationSeconds`
   （越界值夾到邊界值本身，非落回預設——因為值仍是「有意義的數字」只是
   超出約束範圍，語意上應收斂到最近合法邊界；只有「無意義的數字」
   （NaN/Infinity）才落回預設值，兩者處理方式刻意不同）

**夾制語意（acceptance 要求說明）**：
- 有限但越界（如 0.1、5.0）→ 夾至最近邊界（0.5 / 3.0）
- 非有限（NaN、+Infinity、-Infinity）→ 落回預設值 1.5 秒且記錄日誌
- 邊界值本身（恰為 0.5 或 3.0）→ 不受影響，原樣通過

**範圍決策**：僅在 `fromJson`（read-model 外部輸入解析路徑）落地夾制，
不變動 `copyWith` / 建構子。const 建構子的 initializer list 僅允許
potentially-constant expression，無法呼叫任意函式做 clamp；而
`copyWith` 的呼叫端目前僅有測試與尚未實作的 W4 設定面板（該面板的
UI 元件本身會依 SPEC 限制輸入範圍），與 ticket `how.strategy`
「於 fromJson 解析後 clamp...或於建構子收斂」二擇一的第一選項一致，
且與 ticket `where.layer` 標註「CursorLocatorDomain read-model 範圍」
（僅涵蓋外部輸入解析）吻合。

### 修改的檔案

- `lib/models/settings_model.dart`：新增 `import 'dart:developer'`、
  頂層 `_tag` 常數、`_asClampedDuration` 函式，`fromJson` 改用該函式
