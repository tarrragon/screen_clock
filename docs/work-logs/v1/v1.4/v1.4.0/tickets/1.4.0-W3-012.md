### 問題根因

兩項改動共享同一病理：**狀態的生命週期與它所描述的對象不一致**。

| 項目 | 現況 | 位置 |
|------|------|------|
| `generation` | 控制器層級 ivar，描述的是「哪一次 session」卻活在 session 之外，故 `endPlayback` 必須手動遞增來模擬 session 消滅 | 392-403、501、715 |
| `handleFrame` 雙 guard | 世代比對與 session 取出分兩行，兩者實為同一問題「這幀屬於當下存活的 session 嗎」 | 566-568 |
| `handleDeadline` 的 `session != nil` | 現結構下不可達（`endPlayback` 必遞增世代，第一個 guard 已擋下），重構後成為唯一承重檢查 | 694-699 |
| `updateTargetScreenIfNeeded` | 名為「判定並更新 session」，卻順手戳了不在參數列上的 `frameDriver` | 663-671 |

- `followCursorScreen:627`（`.fellBackToMain` 分支）

### WRAP 決策記錄（PM 派發前，2026-08-04）

**W（擴增選項）** — 反向思考推翻原框架。原框架「函式怎麼把訊號傳出去」的相反論述為：搬 surface + driver 改綁 + 記錄 screenFrame 是同一原子操作，拆開反而讓「對準螢幕」散在兩處。問題重寫為「螢幕搬遷操作的協作者該怎麼表達在簽名上」後重跑，得 5 個實質方案。

| # | 方案 | 結果 |
|---|------|------|
| 1 | 不動，acceptance 第 3 條顯性豁免 | 未採納 |
| 2 | 副作用外提，回傳 `CGDirectDisplayID?` | **採納** |
| 3 | `frameDriver` 改顯式參數，副作用留內 | R 階段殺 |
| 4 | CQS 拆分（static 純判定 + `migrate` 執行） | R 階段殺 |
| 5 | 只改名為 `migrateToScreenIfNeeded` + 註解明列副作用 | 未採納 |

**R（現實檢驗）**

- 基本率：Fowler 對「函式做了名字沒說的副作用」的解法排序為 Rename Method / Separate Query from Modifier / Move side effect to caller，第三項適用前提是**單一呼叫端**，本例 3 處呼叫點不成立。
- 方案 3 殺於零資訊增益：`frameDriver` 是建構子注入的 `let` property，不隨呼叫變動，傳入只是把 `self.` 換寫法。
- 方案 4 殺於為抽而抽：判定僅 `entry.frame != session.screenFrame` 一行，不具本檔既有三個 static 純函式（`normalizedProgress` / `layerPoint` / `fadeAlpha`）的計算份量。

**A（拉開距離）** — 悖論檢查點出唯一實質張力：方案 2 保護「簽名誠實」卻製造重複，抵觸 W3-009 剛建立的「消除逐字重複」價值。化解手段為先合併 `followCursorScreen` 兩個 case（本來就該合併，僅差一行 NSLog），使 3 處呼叫點降為 2 處，且該 2 處語意上是兩個不同時機各自對準螢幕，非同碼寫兩遍。**此合併為方案 2 成立的必要前置，屬本票範圍。**

**P（準備好犯錯）** — 三個預想失敗原因與早期警訊見下方「防護要求」。

### 實作方向

**改動一：generation 改 allocator + epoch**

- `PlayingSession` 增 `let generation: UInt64`，於建立時自控制器的 `nextGeneration` 配發。
- 控制器保留 `nextGeneration`（僅 `startNewPlayback` 遞增），移除原 `generation` ivar。
- `handleFrame` / `handleDeadline` 雙 guard 併為單一 guard，語意為「這幀屬於當下存活的 session」：
  `guard let currentSession = session, frameGeneration == currentSession.generation else { return }`
- `endPlayback` 移除世代遞增（`session = nil` 本身即為世代失效）。
- `resetExistingPlayback` 的 `scheduleDeadline(generation:)` 改傳 `currentSession.generation`。
- 註解隨結構簡化改寫，刪去「重置刻意不遞增」長段（392-403），不得殘留描述舊結構的敘述。

**改動二：副作用邊界（依 WRAP 方案 2）**

1. 先合併 `followCursorScreen` 的 `.matched` 與 `.fellBackToMain`：switch 只取 index，`.fellBackToMain` 的 NSLog **必須保留在該分支內**，合併後統一走一次搬遷處理。
2. `updateTargetScreenIfNeeded` 改回傳 `CGDirectDisplayID?`，移除 `frameDriver.retarget` 呼叫。non-nil 表示已搬遷且該 displayID 需 retarget。
3. **兩個呼叫端**（`followCursorScreen` 與 `resetExistingPlayback`）各自以 `if let` 接住並呼叫 `frameDriver.retarget`。
