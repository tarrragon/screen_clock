### AC 與 SPEC 衝突裁決（2026-07-31，用戶裁示）

原 AC 第 3 條與 `how.strategy` 要求「設定面板顯示失敗原因」，與 SPEC-008 EX-06-01 明訂的「使用者提示：無 GUI 提示」直接衝突。

**裁決：以 SPEC 為準**，AC 第 3 條與 `how.strategy` 已同步改寫。**Why**：SPEC 是權威來源，ticket AC 是建票當下對規格的轉述，轉述漂移應向規格收斂而非反向。**Consequence**：本票**不動** `lib/widgets/settings_panel.dart`，檔案範圍收在 platform / state / constants 三處。註冊失敗的處理為「warning 日誌 + 定位器維持停用 + app 其餘功能不受影響」。**Action**：若日後判定靜默失敗對使用者不友善，走 SPEC 變更票而非在本票夾帶 UI。

### 設計決策點（實作者需在 Solution 回應）

- **D1 註冊邏輯落點與可測性**：`hotkey_manager` 是 plugin，單元測試無法真實註冊。既有 `_registerHotKey()` 直接寫在 `_ScreenClockAppState` 內、對 `hotKeyManager` 全域單例硬相依，該形態無法被純 Dart 測試覆蓋。本票應把「註冊 / 解除 / 失敗處理」抽為可注入替身的獨立單元（參照 `lib/platform/` 既有形態），`main.dart` 只留接線。抽出後 `Cmd+Opt+,` 是否一併遷移由實作者判斷——若判斷屬既有技術債且會擴大本票範圍，走 Spawn Requests 另票，不夾帶。
- **D2 生命週期綁定語意**：UC-06 06c 明訂停用後「該組合鍵回歸系統預設行為」，故必須真正 `unregister`，不可只在 handler 內 early return。`SettingsController` 是 `ValueNotifier`，監聽時需自行去重（僅在 `cursorLocatorEnabled` 真的翻轉時動作），避免任一設定變更都重複註冊。dispose 時解除註冊。
- **D3 觸發後的參數換算**：`cursorLocatorEffectDurationSeconds` 是秒（double），`CursorLocator.play` 收 `Duration`。本票直接取設定值換算即可，**值域 0.5-3.0 的執行期夾制屬 1.4.0-W2-010 範圍，本票不做**，避免兩票重疊實作同一夾制。
- **D4 日誌通道**：新增程式碼一律用 `dart:developer` 的 `developer.log`（observability-rules 規則 2），註冊失敗以 `level: 900` 記錄。`lib/main.dart` 既有 `debugPrint` 屬 1.4.0-W2-018 收斂範圍，本票不擴散新的 `debugPrint`，也不順手改既有的。
- **D5 常數集中**：組合鍵（key + modifiers）定義進 `AppCursorLocator`，禁止在註冊處硬編碼 `PhysicalKeyboardKey.keyL` 或 modifier 陣列字面。

## Solution

新增 `lib/platform/cursor_locator_hotkey_controller.dart`：`CursorLocatorHotkeyController` 依 `SettingsModel.cursorLocatorEnabled` 的翻轉註冊 / 解除 `Cmd+Option+L`，觸發時呼叫 `CursorLocator.play`。`lib/app_constants.dart` 新增 `AppCursorLocator.hotkeyPhysicalKey` / `hotkeyModifiers` 兩個原子常數；`lib/main.dart` 於 `ScreenClockApp` 新增建構子參數並在 `initState`/`dispose` 呼叫 `start()`/`stop()`。

**D1 註冊邏輯落點與可測性**：抽出 `HotKeyRegistrar` 抽象介面（`register`/`unregister`），預設實作 `HotkeyManagerRegistrar` 委派全域單例 `hotKeyManager`；`CursorLocatorHotkeyController` 建構子可注入替身，測試以 `_FakeHotKeyRegistrar` 記錄呼叫序列，不觸真實系統 API。既有 `_registerHotKey()`（設定面板 `Cmd+Opt+,`）判斷屬既有技術債，若一併遷移會擴大本票範圍，故不夾帶——已用 `ticket track add-spawn-request` 記錄於 Spawn Requests。

**D2 生命週期綁定語意**：`start()` 依當下 `cursorLocatorEnabled` 同步初始狀態並 `addListener`；`_onSettingsChanged` 僅在 `enabled == _lastEnabled` 不成立（真的翻轉）時動作，其餘設定變更（時長、主色調）不觸發重複註冊/解除（測試「非啟用開關的設定變更不觸發重複註冊」驗證）。停用時走 `_unregister()` 真正呼叫 `registrar.unregister`，非僅忽略觸發（UC-06 06c）。`stop()` 移除監聽並解除已註冊熱鍵。

**D3 觸發後的參數換算**：`_onTriggered()` 於觸發當下（非註冊當下）讀取 `_settings.value`，以 `(seconds * Duration.millisecondsPerSecond).round()` 換算為 `Duration`；測試「觸發時讀取當下最新設定值，非註冊當下快照」驗證註冊後變更設定、觸發時仍拿到最新值。值域 0.5-3.0 執行期夾制屬 1.4.0-W2-010（已由另一票落地於 `SettingsModel.fromJson`/`copyWith`），本票未重疊實作。

**D4 日誌通道**：`_register`/`_unregister` 失敗皆用 `developer.log(..., level: 900)`，未新增 `debugPrint`；`lib/main.dart` 既有 `debugPrint` 未觸碰（屬 1.4.0-W2-018 範圍）。

**D5 常數集中**：`HotKey` 建構子非 `const`，無法在 `AppCursorLocator` 直接組出常數物件，故拆為 `hotkeyPhysicalKey`（`PhysicalKeyboardKey`）與 `hotkeyModifiers`（`List<HotKeyModifier>`）兩個原子常數，於 `_register()` 組裝 `HotKey`；註冊處無 `PhysicalKeyboardKey.keyL` 或 modifier 陣列字面硬編碼（測試「鍵值引用 AppCursorLocator 常數」驗證）。

修改檔案：`lib/app_constants.dart`（新增兩常數）、`lib/main.dart`（wiring）、`lib/platform/cursor_locator_hotkey_controller.dart`（新檔）、`test/platform/cursor_locator_hotkey_controller_test.dart`（新檔，9 案例）、`test/widget_test.dart`、`test/fullscreen_clock_visibility_test.dart`（既有 `ScreenClockApp` 建構呼叫補新參數）。

**Phase 4（多視角審查）**：已派發 `/parallel-evaluation`（basil/complexity/coupling/linux/redundancy 五視角），結論詳見對應審查回覆與後續 commit 記錄（如有發現另建 Ticket，見 Spawn Requests）。
