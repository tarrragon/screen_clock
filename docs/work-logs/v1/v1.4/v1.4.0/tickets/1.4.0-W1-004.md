### 產物一：docs/app-use-cases.md（UC SSOT 彙總檔）

uc_registry.py 的解析規則（實作即規範，須嚴格對齊）：

| 元素 | 正則 / 格式 | 用途 |
|------|-----------|------|
| UC 標題行 | 兩個井號 + 空格 + UC-XX + 冒號 + 空格 + 標題 | 白名單解析錨點 |
| UC 編號 | 兩位數零填充（UC-01，非 UC-1） | VALID_UC_FORMAT_RE 判定 |
| 主流程區塊 | 三個井號 + 空格 + 主要成功場景 | get_uc_summary 摘要來源 |
| 主流程步驟 | 數字 + 點 + 空格 + 兩個星號開頭 | MAIN_FLOW_STEP_RE 匹配 |

須涵蓋的 UC：UC-01 / UC-02 / UC-03 / UC-06（既有分散檔）+ UC-04 / UC-05（本 ticket 只列標題與主流程骨架，完整用例文件由 1.4.0-W1-005 補建）。

內容來源：docs/usecases/UC-01-launch-overlay-clock.md、UC-02-click-through-interaction.md、UC-03-exit-overlay.md、UC-06-locate-cursor.md 的標題與主要成功場景。UC-04 / UC-05 的行為依 docs/spec/input/SPEC-007-mouse-button-binding.md 與 v1.3.0 實作反推。

彙總檔與分散檔的關係：分散檔是完整用例（含例外場景、驗收條件），彙總檔是編號白名單 + 主流程摘要。兩者內容須一致，不可各自漂移。

### 產物二：docs/spec/uc-numbering-convention.md

須涵蓋章節（uc_registry.py docstring 指名第 3 節與第 5 節）：

| 節 | 內容 | 來源 |
|----|------|------|
| 第 1 節 | 編號格式：UC-XX 兩位數零填充；禁止三位數、禁止偽子樹（UC-01.4 形式） | VALID_UC_FORMAT_RE |
| 第 3 節 | SSOT 解析規則：檔案位置、標題行格式、單一來源原則（消費端一律複用 uc_registry，禁自行實作） | USE_CASES_SPEC_RELATIVE_PATH + UC_HEADING_RE |
| 第 5 節 | 豁免範圍：docs/work-logs/、test/fixtures/、tests/fixtures/、docs/spec/ 四類路徑前綴；SSOT 自身；UC-Pattern 設計模式標註（UC- 後接大寫字母） | EXEMPT_PATH_PREFIXES + UC_PATTERN_EXEMPT_RE |
| 第 6 節 | 跨專案適配表：本專案 SSOT 路徑為 docs/app-use-cases.md | USE_CASES_SPEC_RELATIVE_PATH 註解 |
