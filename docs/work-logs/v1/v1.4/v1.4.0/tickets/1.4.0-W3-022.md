## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

（選填：修復方式概述、修改的檔案和驗證方式）

---

統一 contentsScale 下發至單一位置：`CursorLocatorCompositeRenderer` 新增 static
函式 `synchronizeSublayerContentsScale(on:)`，於 attach 完成三個 renderer 的
attach 後呼叫一次，把宿主 layer 當下的 contentsScale 套用到全部 sublayer
（Spotlight 的 dimLayer/holeMask、BorderFlash 的 borderLayer、Ripple 的三個
ringLayer）。宣告為 static 而非依賴 composite 實例，是因為搬遷路徑
`WindowCursorLocatorSurface.move(toScreenFrame:)` 不持有 composite 實例，仍需
呼叫同一份邏輯完成搬遷後重發，因此該函式改為兩個呼叫端共用的單一實作而非各自
複製。

搬遷路徑：`move` 內既有的 `hostView.synchronizeHostedLayer()` 只對齊 hosted
layer 自身；新增一行呼叫 `CursorLocatorCompositeRenderer
.synchronizeSublayerContentsScale(on: contentLayer)` 補上 sublayer 的重發。

同步移除 `CursorLocatorRippleRenderer.attach` 內原本「一次性複製」的
`ringLayer.contentsScale = layer.contentsScale`（Ripple 是三個 renderer 中
唯一原本有做但做得不完整的一支），改由 composite 統一下發，滿足 acceptance
第 3 條「下發由單一位置負責，renderer 內不各自處理」。

修改檔案：
- macos/Runner/CursorLocatorEffectWindow.swift（新增 static 函式、attach 呼叫、move 呼叫）
- macos/Runner/CursorLocatorRippleRenderer.swift（移除一次性複製）
- macos/RunnerTests/CursorLocatorEffectCompositionTests.swift（新增 attach 後對齊、事後改值重發 2 個測試）
- macos/RunnerTests/CursorLocatorSurfaceContractTests.swift（新增搬遷後 sublayer 重發 1 個測試）

驗證方式：以人工設偏離值的 sublayer 模擬「搬遷前殘留舊 scale」，斷言呼叫後被
重新對齊，不倚賴實機真實跨 backingScaleFactor 螢幕（單機測試環境通常只有一種
scale，此法涵蓋邏輯正確性而非依賴硬體）。

### 自檢結果
- 三明示：Solution 各段落均含 Why（CoreAnimation 不傳播 contentsScale 給
  sublayer）/ Consequence（Retina 上光柵化輸出解析度減半）/ Action（composite
  static 函式 + 兩處呼叫）。
- 禁用字/emoji：無。
- 命名：`synchronizeSublayerContentsScale` 為動詞片語，語意明確。
- Phase 4 重構評估：程式碼品質 A（單一下發函式取代原本 Ripple 的重複邏輯，
  無新增技術債）。重構需要：否。結論：現行實作已滿足「單一位置」約束，無需
  進一步重構。
