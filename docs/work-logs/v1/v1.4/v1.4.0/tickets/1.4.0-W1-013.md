## Context Bundle

### 規範依據與判定順序

- .claude/skills/doc/SKILL.md — 六種文件類型定義（建立端，權威）
- .claude/rules/core/tool-output-trust-rules.md 規則 6 — 驗證器警告與工具自動產出衝突時，先查建立端定義；判定順序為 canonical 常數 > 驗證端清單 > 文件描述

本票的修正方向由此判定順序決定：SKILL.md 定義 domain-map.md 為 first-class 文件的固定檔名、指名 uc-numbering-convention.md 的位置，validate-filenames 的豁免清單是待同步的下游。修驗證器，不改文件。

### 現況證據（已由 PM 實測，代理人須獨立重新驗證，PC-162）

執行 doc validate-filenames 目前輸出：
  檔名不符慣例（配號器盲區）: docs/spec/uc-numbering-convention.md（應以 SPEC-數字 開頭）

根因位置：.claude/skills/doc/doc_system/commands/validate.py 的 _fixed_name_exemptions()，其 glob 樣式為 *-spec-template.md。

實測推導結果（ls .claude/skills/doc/templates/*-spec-template.md）只有兩個模板：component-library-spec-template.md、design-system-spec-template.md，故豁免清單僅含 component-library-spec.md 與 design-system-spec.md。

### 兩類落網文件

| 文件 | 為何落網 | SKILL.md 依據 |
|------|---------|--------------|
| docs/spec/uc-numbering-convention.md | 無對應模板，任何從模板推導的機制都涵蓋不到 | SKILL.md 第 54 行指名此路徑 |
| docs/spec/{domain}/domain-map.md | 模板名為 domain-map-template.md，不符 *-spec-template.md 樣式 | SKILL.md 六種文件類型表列 DomainMap |

domain-map.md 目前尚未存在（由 1.4.0-W1-006 建立，該票 blockedBy 本票）。修正須同時涵蓋此未來案例，不可只修當下報錯的那一個。

### 修正方向候選（擇一並記錄理由）

| 候選 | 說明 | 風險 |
|------|------|------|
| A 放寬 glob 為 *-template.md | 讓所有模板推導固定名 | data-contract-template.md 會推出 data-contract.md，但實際 data-contract 檔案帶 SPEC-NNN 前綴，多一個無害的豁免名 |
| B 顯式豁免清單常數 | 在 constants.py 定義 FIXED_NAME_EXEMPTIONS 集合，與模板推導聯集 | 新增固定命名文件時須手動維護，但可涵蓋無模板的 convention 檔 |
| C A + B 併用 | 模板推導 + 顯式清單補無模板者 | 兩個來源，須文件說明各自職責 |

無論擇何案，uc-numbering-convention.md（無模板）都須靠顯式宣告涵蓋，純模板推導不可能涵蓋它。

### 執行約束

- 不修改 docs/ 下任何文件（不改檔名、不搬位置）
- 既有 8 個 SPEC 檔案的檢查行為須不變（frontmatter id 與檔名前綴一致性檢查照舊）
