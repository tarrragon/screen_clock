### 世代序號設計偏離 Phase 3a 字面（有意為之，非缺陷）

Phase 3a 虛擬碼在「重置既有播放」與「建立新 surface」兩分支皆寫「遞增世代
序號」。本實作**重置分支不遞增**：driver 於重置時只 `retarget`、不重呼
`start()`，`onFrame` 閉包仍是同一個、其捕捉的世代值不會被重建。若重置也
遞增，會使該閉包捕捉的世代永久落後於 `self.generation`，導致重置後所有
後續幀被誤判為過期而永久停止推進（elapsed 停滯、無法自然結束）——用
T2.C-04/05 反向推導可驗證：若照字面遞增，這兩案例會失敗。世代序號只在
「建立新 surface」（`driver.start()` 真正重啟）與「結束子程序」（`driver.stop()`
真正停止）遞增，精確對應其保護意圖：攔截已停止／已結束的舊 driver 產生的
在途幀，而非攔截「同一個仍在運作的 driver 於重置後的正常後續幀」。已於程式
碼內以文件註解說明此設計理由。

### Phase 3a 對本票的關鍵約束

1. **四條結束路徑必須共用單一「結束」子程序**（停驅動 → 取消逾時 → 關閉 surface → 釋放持有 → 狀態設閒置 → 遞增世代序號）。自然結束、螢幕歸零、逾時、主動停止四者皆走同一出口。Phase 3a 明指這是「十次觸發無洩漏」在所有路徑一致成立的結構前提；各路徑各自收尾必有某條漏掉其中一步。
2. **在途幀以世代序號攔截**（每幀第一步：幀所屬世代不等於當前世代即直接返回）。Phase 3a 稱此為崩潰防線。
3. **play 的任何拋出路徑結束後，狀態必須仍為閒置**，且無殘留的已排程逾時或已啟動驅動。
4. 測試端 log 物件的**持有方向必須單向**：spy 與 driver 各自持有 log 參照，log 不得持有 spy 或 driver。否則 close 計數與 weak 為 nil 的雙訊號無法並存。

### 本票不做的事

不建立 production surface 與驅動（真實 NSWindow、CVDisplayLink）、不碰 `MainFlutterWindow.swift`、不建立 `CursorLocatorErrorMapping.swift`。三者皆屬 `1.4.0-W2-006.2.2`。本票不得引入任何 Flutter 型別依賴——`CursorLocatorEffectWindow.swift` 刻意只依賴 AppKit，混入 Flutter 型別會使測試群組 C/D 被迫連帶引入 Flutter 依賴（N-1 裁定的核心理由）。
