### 驗證過程（含中途發現並修正的設計漏洞）

初版斷言使用 `expect(swiftSource, contains(literal))`（子字串包含）。驗證「Swift 側改字面應轉紅」時發現漏洞：把 Swift 端 `tintArgb` 改成 `tintArgbX` 後，原字面 `tintArgb`仍是新字串 `tintArgbX` 的子字串，`contains` 誤判為仍相符，測試維持綠燈——即改動並未被捕捉，判準「兩個方向都要能捕捉」未達成。

修正方式：改為比對「被雙引號完整包住的字面」（`contains('"$literal"')`），任一側字面只要不逐字相等即會斷開雙引號邊界。修正後重新驗證：

### 要解決的問題

Dart 側 `AppCursorLocator` 與 Swift 側 `CursorLocatorChannel` 各自宣告同一組 method channel 字面（channel 名 / 方法名 / 兩個參數鍵）。兩份宣告之間目前沒有任何自動化關聯，唯一的綁定是兩邊註解互相指認。

任一側字面被改動時的實際行為（Phase 4 linux 視角稱之為三層共振）：

| 層 | 行為 |
|----|------|
| 編譯期 | 兩側各自合法，全過 |
| 單元測試 | 全綠——測試用 mock handler，永不觸及 Swift 端 |
| 執行期 | 實機拋 `MissingPluginException`，而 `cursor_locator.dart` 的 catch-log 正好把它吞掉只寫 log |

三層都不會產生阻斷性訊號，缺陷要到有人看 log 或發現特效不作動才會浮現。

### 判準
