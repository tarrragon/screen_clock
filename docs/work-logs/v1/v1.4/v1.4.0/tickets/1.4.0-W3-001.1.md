### 交付形態

四項基礎全數落在 `macos/Runner/CursorLocatorEffectWindow.swift`，接線點在
`macos/Runner/MainFlutterWindow.swift`。不繪製任何可見內容。

| 基礎 | 落點 | 說明 |
|------|------|------|
| 0..1 normalized progress | `CursorLocatorEffectController.normalizedProgress(elapsed:duration:)` | 純函式；`elapsed` 來自 `handleFrame` 既有的 CVDisplayLink 時間戳相減（未另起時間軸），分母為 request 的 duration；夾限 0...1，`duration <= 0` 視為已播畢回傳上界 |
| 每 frame 一次的游標取樣 | `resolveTarget()` 改回傳 `TargetResolution`（快照 + 該次取樣的游標位置 + 判定結果）；`followCursorScreen` 改回傳 `NSPoint?` | 螢幕重判定與繪製層共用同一次 `locationSampler()` 呼叫；FR-03 與 FR-05 因而不可能取到不同點 |
| tint / duration 接線 | `CursorLocatorEffectRendering` 協定 + `CursorLocatorEffectFrame` 值型別 | `attach(to:tint:duration:)` 於播放開始與重置時交付；每幀 `render(_:)` 帶 progress / elapsed / duration / cursorPointInLayer / tint |
| Swift 側特效常數集中處 | `CursorLocatorEffectConstants` | 目前只含 progress 上下界；三張特效子票的半徑、寬度、週期一律加於此 |

### 設計決定

- renderer 而非直接繪製：控制器只認得 `CursorLocatorEffectRendering`，不認得任何具體特效。production 傳入 `CursorLocatorCompositeRenderer(renderers: [])`，`.2`/`.3`/`.4` 各自把自己的 renderer 加進該陣列即可，彼此不需修改控制器。
- 座標轉換放控制器而非各 renderer：`layerPoint(forCursorLocation:screenFrame:)` 純函式，特效視窗 frame 恆等於螢幕 frame，故僅需減去螢幕原點、不翻轉 y。放在控制器使三個 renderer 收到同一個已轉換的點。
- `renderer` 參數帶預設 nil：既有生命週期／螢幕／錯誤對應三個測試群組不關心繪製，不必為此改寫。
- 常數分處理由：`CursorLocatorTimingConstants` 保持原樣不併入新列舉——它是視窗生命週期的原生自保門檻（淡出窗、逾時寬限），不對使用者可見也不來自 SPEC-008 視覺約束；`CursorLocatorEffectConstants` 只收「畫出來會被看到」的規格數值。兩者邊界已寫入後者的 doc comment。

### 同步移除的過期註記

`CursorLocatorPlayRequest.tint` 原註「目前無消費者……由 1.4.0-W3-001 接手使用」（1.4.0-W3-008 所寫）已改為描述實際流向；`play(_:)` 的「重置時不會換色」亦同步更正為「renderer 重新 attach，時長與主色調換為新請求的值」。

### Phase 4 重構評估

重構需要：否。技術債務：無新增。程式碼品質：A。`handleFrame` 新增一步「交付繪製層」，以 `deliverFrame` 獨立函式承接，維持既有的每步一函式結構；`followCursorScreen` 由回傳 Bool 改為回傳 `NSPoint?`，語意仍是單一職責（重判定並回報該幀取樣），未擴大該函式責任。
