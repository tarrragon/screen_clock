## Context Bundle

### 規範依據

- .claude/skills/doc/doc_system/core/tracking_schema.py — TRACEABILITY_SCHEMA 是權威 schema（建立端）
- .claude/methodologies/data-layer-contract-methodology.md — 契約與測試對應的第三軸定義

### Schema（依 TRACEABILITY_SCHEMA 常數，不可自創欄位）

頂層五個 key：version / mappings / domain_bundle_tests / data_contract_tests / last_updated

| 軸 | key | entry 必填 | entry 選填 |
|----|-----|-----------|-----------|
| 垂直（使用者行為） | mappings | spec / usecase / title | scenarios / alt_scenarios / main_flow / tests |
| 水平（domain 規則） | domain_bundle_tests | bundle / layer / invariants / tests | 無 |
| 第三軸（資料契約） | data_contract_tests | contract_ref / description | tests / no_test_needed / reason / reason_supplement |

三軸各自獨立記錄覆蓋，聯集為完整覆蓋。data_contract_tests 的 tests 與（no_test_needed + reason）互斥：有測試填 tests，明文豁免填 no_test_needed 為 true 並附 reason。

### 三軸的資料來源

| 軸 | 來源 |
|----|------|
| mappings | docs/spec/{domain}/SPEC-NNN-*.md 的 FR 清單；docs/usecases/UC-*.md 與 docs/app-use-cases.md 的場景 |
| domain_bundle_tests | 1.4.0-W1-006 產出的五份 docs/spec/{domain}/domain-map.md 的 bundle 與不變式 |
| data_contract_tests | 1.4.0-W1-007 產出的 docs/spec/data-management/SPEC-009-settings-storage-data-contract.md 的 A 區不變式（INV-xx）與 A.1-A.6 條目 |

### 測試檔實況（PM 盤點，代理人須自行重新確認）

專案共 13 個 test.dart 檔，分布於 test/ 根層與五個子目錄（input / platform / models / services / widgets）。

tests 欄位填寫規則：

- 路徑須經 ls 驗證真實存在，禁止推測檔名
- 一個條目可對應多個測試檔
- 查無對應測試者留空（不填 tests 欄位），不可填「待補」等佔位字串使覆蓋看似完整
- data_contract_tests 軸若判定某條目本就不需測試，填 no_test_needed 為 true 並於 reason 說明理由

未覆蓋項如實留空是本票的核心價值——traceability 的用途是暴露缺口，虛填會使它失去意義。

### 缺口處理
