#### 一、目的與範圍

讓 `play` 呼叫能在「游標當下所在的螢幕」建立唯一一個特效視窗、播放使用者設定的時長後淡出並確實釋放，且整條路徑的判定邏輯、生命週期狀態與視窗屬性皆可被 XCTest 斷言。核心設計原則：**把「決定在哪播」抽成純資料運算，把「真的開視窗」隔在協定後面，把「時間怎麼流」交由呼叫端注入**，使 acceptance 1/2/3/4/5 皆有自動訊號，只留視覺外觀走實機驗證。

#### 二、介面契約

##### 2.1 螢幕幾何快照與座標系

判定所需的螢幕資訊由呼叫端在「取樣當下」建構為值型別快照傳入，判定層不接觸 `NSScreen`：

```swift
/// 一次判定所需的螢幕幾何快照。
/// 播放期間每幀重新建構，顯示器熱插拔因此即時反映，不需另訂閱
/// didChangeScreenParametersNotification。
struct CursorScreenSnapshot: Equatable {
  struct Entry: Equatable {
    /// 全域座標（AppKit 左下原點）。第二螢幕位於主螢幕左方或上方時
    /// origin 為負值，判定不得假設非負。
    let frame: NSRect
    /// 供 frame driver 綁定螢幕更新率用（SPEC-008 FR-03）。
    let displayID: CGDirectDisplayID
  }

  /// 依 `NSScreen.screens` 原始順序；命中取「第一個」依賴此順序。
  let entries: [Entry]
  /// `NSScreen.main` 在 `entries` 中的索引；取不到 main 時為 nil。
  /// entries 為空時必為 nil。
  let mainIndex: Int?
}
```

**座標系契約**：本節所有 `NSPoint` / `NSRect` 一律為 AppKit 全域座標，原點在主螢幕左下、y 軸向上。與 `MainFlutterWindow.swift` 內 `FullscreenCoverageDetector` 使用的 CGWindowList 左上原點座標系不同，兩者不可混用。Phase 2 須有負座標排列的案例。

##### 2.2 螢幕判定（子票 .1）

```swift
/// 判定結果。以型別區分三條語意不同的路徑，呼叫端無須再比對回傳值
/// 即可決定是否記 E_CL_SCREEN、是否可播放。
/// index 為 CursorScreenSnapshot.entries 的索引。
enum CursorScreenResolution: Equatable {
  /// 找到 frame 涵蓋游標的螢幕（SPEC-008 FR-02 正常路徑）。
  case matched(index: Int)
  /// 無涵蓋螢幕，退回 main（EX-06-02 復原路徑，呼叫端須記 E_CL_SCREEN）。
  case fellBackToMain(index: Int)
  /// 連 main 都取不到（無可用螢幕）。呼叫端視為不可播放。
  case unavailable
}

enum CursorScreenLocator {
  /// 純函式：不讀取任何全域狀態，輸出只由兩個參數決定。
  static func resolve(
    cursorLocation: NSPoint,
    in snapshot: CursorScreenSnapshot
  ) -> CursorScreenResolution
}
```

判定語意（Phase 2 須逐項出案例）：

| 條件 | 回傳 |
|------|------|
| 存在 `frame` 涵蓋 `cursorLocation` 的 entry | `.matched(index:)`，取索引最小的命中者 |
| 無涵蓋者且 `mainIndex != nil` | `.fellBackToMain(index: mainIndex!)` |
| 無涵蓋者且 `mainIndex == nil`（含 `entries` 為空） | `.unavailable` |
| 多個 entry 同時涵蓋（重疊排列） | `.matched` 取索引最小者，不做面積或距離仲裁 |

涵蓋判定採 `NSRect.contains(_:)` 的半開區間語意：`minX <= x < maxX`、`minY <= y < maxY`。故相鄰螢幕的共用邊界座標歸屬**該座標等於其 `minX`／`minY` 的那個螢幕**（語意等同 `NSPointInRect`），不會同時命中兩個，也不會兩個都不命中。此語意為契約的一部分，Phase 2 須有邊界座標案例鎖定（對應「場景 3 邊界座標」）。

> **PM 修訂（Phase 1.5，2026-07-31）**：本段原句為「故相鄰螢幕的共用邊界座標歸屬左／下側螢幕」，與自身的半開區間定義及 §4 場景 3 相反——代入 `[0,1920)` 與 `[1920,3840)`，x=1920 對前者為 `0 <= 1920 < 1920` 即 false、對後者為 `1920 <= 1920 < 3840` 即 true，故歸屬後者。原句由 linux 與 basil 兩個視角獨立指出，一致性視角的交叉檢查表則將此格誤判為「一致」。修訂改以 API 語意描述取代方向詞：方向隨座標系而變，`NSPointInRect` 的語意不變。教訓已記錄為 `PC-SCLK-006`。

```swift
  /// 無任何可用螢幕（CursorScreenResolution.unavailable）。錯誤碼字面 E_CL_SCREEN。
  case noAvailableScreen
}

final class CursorLocatorEffectController {
  var state: CursorLocatorPlaybackState { get }

  /// 觸發或重置播放。
  /// - .idle 時建立 surface 並開始播放
  /// - .playing 時「重置」既有 surface：elapsed 歸零、tint/duration 換為新
  ///   請求、alpha 復位為 1、必要時搬遷至新目標螢幕；不建立第二個
  ///   surface（UC-06 替代場景 06b）
  /// - throws CursorLocatorError.windowCreationFailed / .noAvailableScreen
  func play(_ request: CursorLocatorPlayRequest) throws

  /// 立即結束播放並釋放 surface（app 結束或測試 teardown 用）。
  /// 後置條件：state == .idle、surface 已 close 且控制器不再持有、
  /// 後續在途幀一律被忽略（見「時間與執行緒契約」的 generation token）。
  /// .idle 時為 no-op，不 throw。
  func stop()
}
```

> **移除 `activeSurfaceCount`**（Phase 1.5 P0-2，採 linux 裁定）。該屬性與 `state` 為同一位元存兩份，且計數歸零只證明控制器不再持有、證不了 `NSWindow` 已 dealloc，留著會讓人誤以為 acceptance 5 已被測到。改由測試端斷言：spy surface 的 `close()` 呼叫次數，加上對 spy 的 `weak var` 參照在控制器釋放後為 nil。

##### 2.6 淡出契約

淡出**含在 `duration` 之內**，最後 `fadeDuration = min(0.2, duration * 0.4)` 秒為淡出窗：`alpha` 由 1.0 線性降至 0.0，`elapsed >= duration` 時 surface 關閉。故單次播放的總時長恆等於使用者設定值。

擇「含在內」而非「時長之後再淡出」的理由：FR-06 的時長範圍下限為 0.5 秒，外加固定 200 ms 淡出等於在最短設定上超出 40%，使用者設定的數字與實際觀察不符；且「總時長 == 設定值」是可直接斷言的不變量，「設定值 + 未載入 SPEC 的常數」不是。

> **與 UC-06 主場景 5 字面的偏離**：UC-06 寫「依使用者設定的特效時長**後**整層淡出」，字面讀為淡出在時長之外。本節取「含在內」，屬規格字面偏離，須由 PM 決定是修 UC-06／SPEC-008 措辭或推翻本裁定。Phase 2 應以本節契約設計案例，若 PM 裁定相反，僅需改 `fadeDuration` 的起算基準，介面不變。

淡出的執行歸屬見下方「衝突裁定：`CursorLocatorSurface` 的淡出方法存廢」。

##### 2.7 時間與執行緒契約

| 項目 | 契約 |
|------|------|
| `onFrame` 參數語意 | **絕對時間戳**（單調遞增，production 為 `CACurrentMediaTime()`），非幀間隔 |
| `elapsed` 計算 | `timestamp - startTimestamp`，`play` 當下記錄起點 |
| 結束判定 | `elapsed >= duration` 即結束。睡眠喚醒後時間戳大幅前進只會**提早**結束，不會停滯 |
| 逾時保險 | `play` 時經 `CursorLocatorDeadlineScheduling` 安排 `duration + 0.5` 秒的一次性回呼；到期時若仍在播放則強制結束並釋放。涵蓋顯示器休眠導致 CVDisplayLink 停擺、幀完全不再送達的情形——此為 acceptance 5 的真實洩漏向量，手動 driver 測不到，故以獨立注入點覆蓋 |
| 執行緒 | 所有公開方法與 `onFrame` 皆於 main thread；控制器不做鎖 |
| 過期幀 | 控制器持有 `generation: UInt64`，`play` / `stop` 各遞增一次；`onFrame` 閉包捕捉當下 generation，不符即直接返回 |

`stop()` 的後置條件以 generation token 保證，而非要求 driver 的 `stop()` 同步「返回後不再有回呼」——後者在 CVDisplayLink 的獨立執行緒模型下需阻塞等待，而 `stop()` 可能由 `onFrame` 內部（播放自然結束）呼叫，阻塞即自我死結。token 攔截讓在途幀對已 `close()` 的 surface 呼叫 `move` / `setAlpha` 這條 CVDisplayLink 典型崩潰路徑結構性消失（Phase 1.5 P0-11 的第二個選項）。

##### 2.8 每幀行為

`onFrame` 回呼內依序：

1. generation 不符 → 返回
2. 重建螢幕快照（`CursorScreenSnapshotProviding`）、取樣游標（`CursorLocationSampling`）
3. `CursorScreenLocator.resolve` 重新判定目標螢幕
   - `.matched` / `.fellBackToMain` 且 frame 與當前 surface 所在不同 → `surface.move(toScreenFrame:)` + `driver.retarget(displayID:)`；`.fellBackToMain` 另記 E_CL_SCREEN log，不中斷播放
   - 同一螢幕 → 不呼叫 `move`，避免每幀搬遷
   - `.unavailable`（播放中螢幕數歸零，如闔蓋）→ 立即結束：停 driver、`close()`、狀態回 `.idle`，記 E_CL_SCREEN log
4. 計算 `elapsed`；落在淡出窗內則 `surface.setAlpha(...)`
5. `elapsed >= duration` → 停 driver、取消逾時保險、`close()` surface、狀態回 `.idle`

顯示器熱插拔因此不需要額外的 `didChangeScreenParameters` 訂閱：每幀重建快照已涵蓋「目標螢幕被拔除」（重判定後搬遷）與「全部螢幕消失」（`.unavailable` 結束）兩條路徑，且完全以注入依賴可測（Phase 1.5 P0-9）。

##### 2.9 視覺特效的擴充點（本票不實作）

FR-03/04/05 三種特效於 1.4.0-W3-001 各自實作 renderer 協定，由控制器建構子以陣列注入；本票注入空陣列即可讓生命週期完整運作。

**本票只宣告擴充點存在與注入形狀，不鎖定方法簽章**，Phase 2 亦不為其撰寫呼叫序列的 spy 測試（Phase 1.5 次要修訂，linux P2）：為尚未實作的功能預先鎖定呼叫順序，W3-001 動手時多半得先拆掉那些測試。控制器對 renderer 的呼叫時機屬 W3-001 的 Phase 1 職責。

因此原稿「場景 5 以 spy renderer 斷言 `reset()` 與未收到第二次 `attach()`」改為以控制器自身可觀測狀態斷言（見場景 7）。

#### 三、衝突裁定：`CursorLocatorSurface` 的淡出方法存廢

Phase 1.5 兩份審查互斥：linux 主張刪除（surface 已交出 `contentLayer`，淡出是 renderer 對圖層做的事，留著等於兩處都能改透明度）；Plan 主張保留（UC-06 主場景 5 要求「整層淡出」，而本票 renderer 為 no-op，刪除則無人執行淡出）。

**裁定：保留，但改名為 `setAlpha(_:)` 並重新定義為視窗層級屬性（`NSWindow.alphaValue`），非圖層 opacity。**

判準與理由：

1. **「整層淡出」在語意上就不是單一特效的職責**。三種特效各有自己的動畫曲線（聚光燈壓暗、邊框閃三次、波紋擴散），若淡出歸 renderer，等於同一份淡出排程要在三個 renderer 內各實作一次，且日後新增特效必須記得補；而它們共同的收尾行為只有一種可能結果——整個視窗消失。這屬 surface 生命週期的收尾階段，與 `close()` 同一層。
2. **linux 指出的職責重疊確實存在，但根因是原命名而非該能力存在**。原 `setOpacity` 是圖層語彙，與 renderer 能碰的 `contentLayer.opacity` 同名同層，故看起來「兩處都能改」。改為 `setAlpha` 並綁定 `NSWindow.alphaValue` 後，職責邊界是型別層級的：renderer 只拿得到 `contentLayer`，碰不到視窗；surface 只動視窗整體 alpha，不動內容。重疊消失，能力保留。
3. 附帶效益：`NSWindow.alphaValue` 對整個視窗合成一次，比讓三個 renderer 各自對圖層做透明度動畫更省，且不會出現三層淡出速率不一致的視覺瑕疵。

本裁定使 UC-06 主場景 5 由本票交付，不改掛 W3-001；驗收對應表已據此列入「場景 12 淡出」。

#### 四、錯誤路徑的介面歸屬

| 場景 | 錯誤碼 | 介面表現 | play 的 channel 回傳 |
|------|--------|---------|---------------------|
| 目標螢幕解析失敗（EX-06-02） | E_CL_SCREEN | `.fellBackToMain`，控制器照常播放 | `result(nil)`，視為成功；僅 NSLog |
| 無任何可用螢幕 | E_CL_SCREEN | `.unavailable` → `throw .noAvailableScreen` | `result(FlutterError(code: "E_CL_SCREEN", ...))` |
| 特效視窗建立失敗（EX-06-03） | E_CL_WINDOW | 工廠 throw → `throw .windowCreationFailed` | `result(FlutterError(code: "E_CL_WINDOW", ...))` |
| 播放中每幀重判定退回 main | E_CL_SCREEN | 僅 NSLog，不中斷、不改變 state | 該次 play 早已回傳，無影響 |
| 播放中螢幕數歸零 | E_CL_SCREEN | 立即結束並釋放，僅 NSLog | 該次 play 早已回傳，無影響 |

判準（與 Problem Analysis「規格落差澄清」一致）：**復原路徑不以 FlutterError 中斷播放**；所有「回報 Dart 側」一律為本次 `play` 呼叫的同步 `FlutterError` 回應，不新增原生至 Dart 的反向 channel 或 EventChannel。會到達 Dart 的 E_CL_SCREEN 語意唯一——無可用螢幕。

`noAvailableScreen` 屬 SPEC-008 未列舉的殘餘情形（螢幕數為 0），歸入 E_CL_SCREEN 而非新增錯誤碼，避免擴張 SPEC 定義的錯誤碼集合。

#### 五、GWT 行為場景

場景編號沿用初版以保持既有引用可解析，另附語意名稱供錨定。

**判定層（子票 .1，純函式）**

- **場景 1（正常判定）**：Given 兩個不重疊 entry 的快照、游標落在第二個的 frame 內；When `resolve`；Then `.matched(index: 1)`。
- **場景 2（間隙退回）**：Given 兩 entry 間存在未涵蓋座標、`mainIndex == 0`；When 以間隙座標 `resolve`；Then `.fellBackToMain(index: 0)`。
- **場景 3（邊界座標）**：Given 兩螢幕於 x=1920 相鄰；When 游標恰在 x=1920；Then 命中右側螢幕（半開區間語意），且僅命中一個。
- **場景 3b（負座標排列）**：Given 第二螢幕位於主螢幕左方（frame origin.x 為負）或上方；When 游標落於第二螢幕；Then `.matched` 指向第二螢幕。
- **場景 3c（無可用螢幕）**：Given `entries` 為空且 `mainIndex == nil`；When `resolve`；Then `.unavailable`。
- **場景 3d（重疊排列）**：Given 兩 entry 的 frame 互相重疊且游標落於重疊區；When `resolve`；Then `.matched` 取索引較小者。

**生命週期層（子票 .2，注入依賴）**

- **場景 4（接線：目標螢幕真的被拿去開視窗）**：Given 游標位於螢幕 B；When `play`；Then `CursorLocatorSurfaceMaking` 收到的引數恰為 B 的 frame 且僅被呼叫一次，`state.screenFrame == B.frame`。（缺此場景時，判定正確但接線永遠傳 main 仍會全綠。）
- **場景 5（單次播放釋放）**：Given `.idle` 與手動 driver；When `play(duration: 1.5)` 後推進時間戳至 +1.5；Then 過程中 `state` 為 `.playing`，結束後 `state == .idle`、spy surface 的 `close()` 恰被呼叫一次。
- **場景 6（釋放後不再持有）**：Given 場景 5 的 spy surface 以 `weak var` 額外持有；When 播放結束並釋放測試端強參照；Then weak 參照為 nil（證 dealloc，非僅計數歸零）。
- **場景 7（06b 重複觸發為重置）**：Given 播放進行至 elapsed 0.8；When 再次 `play`；Then `CursorLocatorSurfaceMaking` 仍只被呼叫過一次、`state.elapsed` 歸零、`state.duration` 為新請求值、surface 的 `close()` 未被呼叫、`setAlpha(1.0)` 復位。
- **場景 8（播放中連按十次）**：Given 播放中；When 於同一次播放期間連續 `play` 十次且期間不推進至結束；Then `CursorLocatorSurfaceMaking` 呼叫次數恆為 1、`close()` 呼叫次數恆為 0、`state` 始終為 `.playing`。
- **場景 9（十次完整播放無洩漏）**：Given 手動 driver；When 連續十次 `play` 並各推進至結束；Then 每次結束後 `state == .idle`、`close()` 累計次數為 10、`CursorLocatorSurfaceMaking` 累計次數為 10，且各次 surface 的 weak 參照皆為 nil。
- **場景 10（06a 跨螢幕跟隨）**：Given 游標取樣序列由螢幕 A 切至螢幕 B；When 推進數幀；Then surface 收到 `move(toScreenFrame: B.frame)` 恰一次（同螢幕連續幀不重複搬遷），driver 收到 `retarget(displayID: B.displayID)` 恰一次。
- **場景 11（熱插拔：目標螢幕消失）**：Given 播放中，快照 provider 於第 N 幀起移除當前目標螢幕；When 推進至第 N 幀；Then surface 搬遷至重判定結果的 frame，播放不中斷。
- **場景 12（熱插拔：螢幕數歸零）**：Given 播放中，快照 provider 於第 N 幀起回傳空 entries 且 `mainIndex == nil`；When 推進至第 N 幀；Then 立即 `close()`、`state == .idle`，且不因此 throw（`play` 早已返回）。
- **場景 13（淡出）**：Given `play(duration: 1.5)`；When 推進至 1.3 之後的各幀；Then `setAlpha` 收到單調遞減且落於 (0, 1) 的值，1.5 前的最後一次為趨近 0；1.3 之前不曾收到小於 1.0 的值。
- **場景 14（逾時保險）**：Given `play` 後手動 driver **完全不送幀**（模擬顯示器休眠導致 CVDisplayLink 停擺）；When 觸發 deadline 樁；Then `close()` 被呼叫、`state == .idle`。
- **場景 15（stop 於播放中）**：Given 播放中；When `stop()`；Then `close()` 恰一次、`state == .idle`、deadline 已取消。
- **場景 16（stop 於 idle）**：Given `.idle`；When `stop()`；Then 無任何 surface 互動、不 throw、`state` 維持 `.idle`。
- **場景 17（stop 後在途幀）**：Given 播放中呼叫 `stop()`；When 對已關閉的 surface 再送一幀（模擬 CVDisplayLink 在途回呼）；Then 該幀被 generation token 忽略——`move` / `setAlpha` / `close` 皆未再被呼叫。
- **場景 18（duration <= 0）**：Given `play(duration: 0)`；When 推進首幀；Then surface 建立後於首幀即 `close()`、`state == .idle`、不 throw。

**錯誤路徑**

- **場景 19（EX-06-03）**：Given 必定 throw 的 `CursorLocatorSurfaceMaking`；When `play`；Then 拋出 `.windowCreationFailed`、`state` 維持 `.idle`、bridge 以 `FlutterError(code: "E_CL_WINDOW")` 回傳。
- **場景 20（退回 main 不中斷）**：Given 游標落於間隙；When `play`；Then 於 main 的 frame 建立 surface、`play` 不 throw、bridge 回傳 `result(nil)`。
- **場景 21（無可用螢幕）**：Given 快照為空且無 main；When `play`；Then 拋出 `.noAvailableScreen`、`CursorLocatorSurfaceMaking` 未被呼叫、bridge 以 `FlutterError(code: "E_CL_SCREEN")` 回傳。

**視窗屬性（app-hosted XCTest，對真實 NSWindow）**

- **場景 22（視窗屬性契約）**：Given production 的 surface 工廠；When 建立 surface；Then §2.5 表中各屬性逐項符合契約值，且視窗未成為 key window。
