#### 現況程式碼（已定位）

`macos/Runner/MainFlutterWindow.swift`：

```swift
/// 側鍵放開：若正在拖曳則離開並消費，否則放行。
private func handleButtonUp(event: CGEvent) -> Unmanaged<CGEvent>? {
  if draggingAction != nil {
    draggingAction = nil
    return nil
  }
  return Unmanaged.passUnretained(event)   // ← Hotkey 綁定走此路徑，穿透
}
```

相關位置：`draggingAction` 宣告 295 行；事件 mask 383-384 行（down 與 up 皆在 mask 內）；分派 444 行 `.otherMouseDown` / 453-454 行 `.otherMouseUp`；`handleButtonDown` 的 Hotkey 分支 478-481 行（呼叫 `synthesizeHotkey` 後 `return nil` 消費）。

#### acceptance 條 3 的可測性前提（Phase 3a 須先解決）

acceptance 要求「XCTest 或 flutter test 覆蓋 Hotkey mouseUp 消費路徑」，但現況無法直接測：

| 障礙 | 說明 |
|------|------|
| `private func` | Swift 的 `@testable import` 只提升 internal 可見度，private 成員仍不可見 |
| 依賴實例狀態 | `draggingAction` 是 `MainFlutterWindow` 的實例屬性，測試需實例化該 window |
| 實例化即觸發 CGEventTap | `MainFlutterWindow` 啟動路徑會建立 event tap，無人值守執行時可能彈出輔助使用權限對話框而阻塞（CLAUDE.md 已載明此風險，`scripts/run-tests.sh` 檔頭註解亦有） |
