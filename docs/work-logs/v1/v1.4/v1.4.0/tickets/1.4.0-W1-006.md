### 每份 domain-map 的必要內容

依模板結構，四要素：

| 要素 | 內容 | 資料來源 |
|------|------|---------|
| bundle 邊界 | 該 domain 內的 bundle 劃分（aggregate / kernel / read-model 分類） | 讀 lib/ 對應目錄的實際結構 |
| 依賴方向 DAG | bundle 之間與跨 domain 的依賴箭頭，須為有向無環 | 讀 lib/ 的 import 關係 |
| 層測試策略 | 每層對應的測試類型與位置 | 讀 test/ 目錄結構 |
| FR 到 bundle 覆蓋表 | 該 domain 每個 spec 的每個 FR 歸屬到哪個 bundle | 讀該 domain 下 spec 的 FR 清單 |

### bundle 實作狀態驗證（PC-APP-012 防護，強制）

第 3 節每個 bundle 標記實作狀態前，必須先驗證目標路徑存在：

- 執行 ls 或 grep 確認 lib/ 下對應目錄或檔案真實存在
- 存在才標「已實作」，不存在標「規劃中」
- 驗證命令與輸出寫入 ticket 的 Test Results 章節

禁止依 spec 描述或檔名推測即標記已實作。本專案 lib/ 現有目錄：input、models、platform、services、state、widgets，以及根層 age_formatter.dart、app_constants.dart、main.dart。

### FR 覆蓋完整性（W2-014 教訓）

domain map 的 FR 覆蓋表須涵蓋該 domain 全部 spec 的全部 FR，不可停在中途。歷史案例：某 domain map 停在 FR-24 漏掉 FR-25/26，靠人工審查才發現。逐份完成後執行 check_domain_coverage.py 機械驗證。

### 執行約束

- 不修改任何 spec 檔案（本 ticket 是新建 domain map，非改 spec）
- 不修改 lib/ 下任何程式碼
- 跨 domain 依賴須雙向一致：若 A 的 map 說依賴 B，B 的 map 不可宣稱依賴 A（DAG 無環要求）

### 驗收驗證命令

| 驗收條件 | 驗證命令 | 期望 |
|---------|---------|------|
| 五份齊備 | ls docs/spec/*/domain-map.md | 5 個檔案 |
| FR 覆蓋 | python3 .claude/skills/spec/scripts/check_domain_coverage.py docs/spec/{domain}/SPEC-NNN-*.md | 逐一 exit 0 |
| bundle 狀態經驗證 | Test Results 章節含 ls/grep 實際輸出 | 每個標「已實作」的 bundle 都有對應驗證輸出 |
| DAG 無環 | 人工檢查五份 map 的依賴宣告一致性 | 無互相依賴 |
