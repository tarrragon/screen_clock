## Context Bundle

### 任務定位

1.4.0-W1-001.1（常數類）與 .2（SettingsModel schema 4）平行派發的銜接修正。兩票檔案互斥可平行，但語意上有依賴：.2 的三欄位預設值應引用 .1 的常數。平行執行使兩者在各自 worktree 中無法看見對方產出，各自決定了預設值，整合後出現不一致。

本票不是回退，兩票的產出皆保留；本票只做對齊。

### 缺陷實況（整合後於 main 觀察）

| 項目 | .1 AppCursorLocator | .2 SettingsModel | SPEC-009 A.1 v4 裁決 |
|------|---------------------|------------------|---------------------|
| 特效時長型別與單位 | int 毫秒（defaultDurationMs = 1500） | double 秒（cursorLocatorEffectDurationSeconds = 1.5） | double 秒，預設 1.5，範圍 0.5–3.0 → .2 正確 |
| 時長範圍 | minDurationMs 500 / maxDurationMs 3000 | 未定義範圍常數 | 0.5–3.0 秒 |
| 主色調 | Colors.blue（MaterialColor） | Color(0xFF2196F3) | Color，預設系統藍 → .2 正確 |
| 預設值來源 | 常數類 | 硬編碼於建構子與 defaults() | 應由常數類單一來源提供 |

兩票各自的測試皆為綠燈（.1 為 136/136，.2 為 142/142），因為兩處定義從未在同一編譯單元中相遇。這正是 1.4.0-W1-011 實測 E3 所述「單位變更無機械訊號」的具體重現。

### MaterialColor 不可用作預設值的實證（來自 .2 Solution）

Colors.blue 的型別是 MaterialColor，與從 ARGB int 經 _asColor 重建的普通 Color 比較時 runtimeType 不符，導致 fromJson(toJson(model)) == model 的 round-trip 相等性測試失敗。.2 因此改用 Color(0xFF2196F3) 並已回填 SPEC-009。本票修正 .1 的 defaultTint 時須沿用同一結論，不可改回 Colors.blue。

### 秒與毫秒的分層（本票須保留的區分）

設定層與傳輸層的單位刻意不同，不是缺陷：

| 層 | 單位 | 理由 |
|----|------|------|
| 設定層（SettingsModel、AppCursorLocator FR-06 預設值） | double 秒 | SPEC-009 A.1 v4 權威定義；面向使用者的設定值 |
| 傳輸層（channel 參數鍵 durationMsArgKey） | int 毫秒 | 原生層 API 慣例 |

本票須維持此區分，並在 Dart 側橋接處（1.4.0-W1-001.3 建立的 lib/platform/cursor_locator.dart）讓秒轉毫秒的換算點有明確命名或註解。若 .3 尚未完成，本票只需確保常數層語意清楚，換算點由 .3 落實。
