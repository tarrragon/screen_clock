### 現況證據（PM 實測，代理人須獨立重現）

在專案根目錄執行三種形式：

| 命令 | 實際輸出 |
|------|---------|
| doc uc verify lib | 錯誤：指定路徑不存在: lib |
| doc uc verify /Users/mac-eric/project/screen_clock/lib | UC 編號驗證通過，無違規 token |
| doc uc verify（無引數） | UC 編號驗證通過，無違規 token |

相對路徑 lib 被解析為 skill 目錄下的 lib（不存在），絕對路徑正常。

### 根因（1.4.0-W1-004 代理人調查，須驗證）

shim（~/.local/bin/doc）以 uv run --directory <skill_dir> doc 形式執行，--directory 使子行程 cwd 變為 .claude/skills/doc，故 CLI 內以 Path(target).exists() 檢查相對路徑時基準錯誤。

此設計來自 ARCH-APP-002（改用 cwd-resolving shim 取代全域 uv tool install），三個 shim（doc / ticket / worktree）由 .claude/scripts/install-skill-clis.py 統一產生，故缺陷共通。

須先讀 ~/.local/bin/doc 的實際內容確認 shim 樣式，再讀 install-skill-clis.py 確認產生邏輯。

### 影響範圍盤點（本票須完成）

列出三個 CLI 中所有接受路徑引數的子命令，逐一判定是否受影響：

| CLI | 已知接受路徑引數的子命令 | 待補 |
|-----|------------------------|------|
| doc | uc verify [path]、uc trace | 掃描其他子命令 |
| ticket | 未知 | 掃描 |
| worktree | 未知 | 掃描 |

盤點方式：grep 三個 skill 的 add_argument 定義，找出語意為路徑的引數。

### 修正方向候選（擇一並記錄理由）

| 候選 | 說明 | 風險 |
|------|------|------|
| A shim 端轉絕對路徑 | shim 在呼叫 uv run 前，將看起來是路徑的引數轉為絕對路徑 | 難以判斷哪些引數是路徑（ticket ID 含點與斜線的情況） |
| B shim 傳遞原始 cwd 環境變數 | 如 SKILL_CLI_ORIGINAL_CWD，CLI 端解析相對路徑時以此為基準 | 需三個 CLI 端各自消費，但語意明確、不誤判非路徑引數 |
| C 改用不切換 cwd 的執行形式 | 如以 PYTHONPATH 或 --project 取代 --directory | 須確認不破壞 ARCH-APP-002 要解決的原始問題（多專案同名 skill 碰撞、源碼即時生效） |

候選 C 須特別驗證：ARCH-APP-002 的設計目標是「shim 依 cwd 所在專案的 git toplevel 解析 skill 源碼」，任何修改不得破壞此行為，也不得使源碼修改需要重新安裝才生效。

### 執行約束

- 修正後三個 CLI 的既有行為（絕對路徑、無引數）不得改變
- 不得要求使用者一律傳絕對路徑（那是用文件補工具缺陷，違反 opinionated-default-design 主張 1）
- 若修改 shim 樣式，須同步更新 install-skill-clis.py 與相關文件（.claude/skills/ticket/SKILL.md 與 doc/SKILL.md 皆有 shim 說明章節）

### 並行安全約束（最高優先）

本票修改 shim 產生器。重跑 install-skill-clis.py 會替換所有並行代理人正在使用的 CLI，可能使其執行到一半的 ticket 操作失敗。

要求：
- 修改 install-skill-clis.py 期間不重新安裝
- 需要驗證新 shim 時，先產生到臨時路徑測試（如 /tmp 下的測試 shim），確認正確後才決定是否正式安裝
- 正式重新安裝前，先執行 ticket track list --status in_progress 確認無其他進行中 ticket；若有，於 Exit Status 記錄並交還 PM 決定安裝時機，不自行安裝
