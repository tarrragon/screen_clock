## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->

行為反寫依據：讀取 `lib/input/mouse_action.dart`、`mouse_binding.dart`、`input_binding_channel.dart`、
`input_binding_controller.dart`、`macos/Runner/MainFlutterWindow.swift`（`InputBindingBridge`）與
`lib/widgets/settings_panel.dart` 的實際實作，未依 SPEC-007 或 PROP-002 描述推測。

發現的實作與 SPEC-007 描述有落差之處（已依實作反寫入 UC，非虛構）：

1. FR-03 聲稱「被綁定鍵的 otherMouseDown / otherMouseUp 皆消費」，但實際 `handleButtonUp` 只在
   `draggingAction != nil`（即 DragScroll 綁定）時消費放開事件；Hotkey 綁定的放開事件並未被消費，
   依原樣放行。已寫入 UC-05 主流程步驟 4 與已知限制。
2. CGEventTap 建立失敗（EX-04-02/EX-05-02）與 hotkey keyCode 查無對應 CGKeyCode（EX-05-03）皆僅
   `NSLog`，查無使用者可見提示或明確重試機制；依約束標註「使用者提示：無，查無對應 UI 呈現機制，
   標註為未定義」，不虛構恢復流程。
3. 拖曳期間的移動事件會被消費（`return nil`），因此系統游標圖示在拖曳滾動期間視覺上不隨滑鼠位移，
   此為讀碼後才發現的可觀察行為，已寫入 UC-04 主流程步驟 2。

ticket_refs 篩選：依 `docs/work-logs/v1/v1.3/v1.3.0/tickets/` 逐筆核對 what/why 與 lib/input/、
MainFlutterWindow.swift 的實作對應，UC-04（拖曳滾動）對應 W1-001/W2-001/W2-002/W2-003/W3-002/
W4-001~004；UC-05（快捷鍵）對應 W1-001/W2-001/W2-002/W2-003/W4-001~004/W5-001/W5-002/W5-004。
W5-003（CHANGELOG/README 文件票）與 W5-005（版本號票）非實作票，不列入 ticket_refs。
