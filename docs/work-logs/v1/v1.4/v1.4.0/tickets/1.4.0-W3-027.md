#### 步驟 2：以 makeHostedLayer 手法重寫的第一版仍無分辨力（診斷過程）

比照 `CursorLocatorEffectCompositionTests.makeHostedLayer`，建立獨立 `LayerHostingView`（已放寬為 internal）掛在最小 `NSWindow` 上，呼叫 `view.setFrameSize(...)` 觸發 `synchronizeHostedLayer()`。移除 disableActions 後執行：`** TEST SUCCEEDED **`——仍無分辨力。

追加診斷測試 `testDiagnosticSublayerFrameChangeIsObservable`（對 hosted layer 的 sublayer 直接寫 frame）：`animationKeys()` 回傳 `["position", "bounds"]`，證實 animationKeys() 觀測手段本身有效，問題出在對「root hosted layer 本身」透過 `setFrameSize` 路徑寫入時觀測不到差異。

追加診斷測試 `testDiagnosticDirectRootLayerFrameWrite`（繞過 `setFrameSize`，直接對 `view.layer?.frame` 賦新值）：`animationKeys()` 回傳 `["bounds", ...]`——證實 root hosted layer 本身可以被觀察到隱含動畫，問題不在 layer 層級而在呼叫路徑。

推論：`NSView.setFrameSize` 對 layer-hosting view 會自行把 hosted layer 的幾何同步到與新 `bounds` 一致（production 註解已提及此 AppKit 行為），使後續 `synchronizeHostedLayer()` 內的 `hostedLayer.frame = bounds` 寫入值與現值相同、CALayer 視為無變更、不產生隱含動畫——與是否停用 action 無關，此路徑對本測試無分辨力。

#### 步驟 3：改為直接呼叫 synchronizeHostedLayer() 並人工使幾何不同步

不經 `setFrameSize`：先以停用 action 的 transaction 把 hosted layer 的 frame 撥到與 `view.bounds` 不同的值（此步驟本身不應計入待測動畫），再直接呼叫 production 受測方法 `view.synchronizeHostedLayer()`，使其內部的 `frame = bounds` 是一次真正的幾何變更。

### 修復方式

1. `macos/Runner/CursorLocatorEffectWindow.swift`：`LayerHostingView` 由 `private final class` 放寬為 `final class`（internal），使 RunnerTests 透過 `@testable import` 直接建構獨立宿主；`WindowCursorLocatorSurface` 仍是唯一 production 建構點，不影響封裝邊界。

2. `macos/RunnerTests/CursorLocatorSurfaceContractTests.swift`：重寫 `testGeometrySyncDoesNotStartImplicitAnimation`：
   - 新增 `makeIndependentHostedLayerView()`：獨立 `LayerHostingView` + 最小 `NSWindow`（比照 `CursorLocatorEffectCompositionTests.makeHostedLayer`，不再經過 `WindowCursorLocatorSurface` 的完整 production 初始化，即 `.screenSaver` 層級／`collectionBehavior`／`orderFrontRegardless` 皆非隱含動畫防護所需，但構成原測試無分辨力的環境差異之一）。
   - 測試改為：commit 初始圖層樹 -> 以停用 action 的 transaction 人工使 hosted layer 與 `view.bounds` 不同步 -> 直接呼叫 production 受測方法 `view.synchronizeHostedLayer()` -> 斷言 `frame == bounds` 且 `animationKeys()` 為空。
   - 不透過 `setFrameSize` 觸發：診斷發現 AppKit 對 layer-hosting view 的 `setFrameSize` 會自行同步 hosted layer 幾何，使後續 `synchronizeHostedLayer()` 的寫入值與現值相同（no-op），無論是否停用 action 皆不產生隱含動畫，對測試無分辨力（詳見 Problem Analysis 重現實驗結果步驟 2）。
