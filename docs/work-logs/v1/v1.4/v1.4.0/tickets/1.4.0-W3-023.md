## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

為 `CursorLocatorEffectFrame` 新增 `layerBounds: CGRect` 欄位，與 `cursorPointInLayer` 同一處（`deliverFrame`）填入，讀自 `session.surface.contentLayer.bounds`。三個 renderer 全面收斂為消費此單一來源：

- **Spotlight**（`CursorLocatorSpotlightRenderer.render`）：刪除 `dim.superlayer?.bounds ?? dim.bounds` 反查分支，改讀 `frame.layerBounds`。
- **BorderFlash**（`CursorLocatorBorderFlashRenderer`）：`attach` 移除 `border.autoresizingMask = [.layerWidthSizable, .layerHeightSizable]`；`render` 新增 `borderLayer?.frame = frame.layerBounds`，逐幀顯式對齊，不再倚賴 AppKit 的隱式 autoresizing 觸發時機。
- **Ripple**：本就不消費 bounds（每幀從 `cursorPointInLayer` 與半徑常數重算），無需改動，僅測試 fixture 補上 `layerBounds` 參數以符合新簽章。

未保留任何舊分支——ticket 前置要求「若某處仍需保留請在 Solution 說明理由」，本案三處皆可依資料結構修正後自然消失，無例外。

### 自檢結果

- `flutter analyze`：本次修改的 4 個檔案（`CursorLocatorEffectWindow.swift` 為 Swift，不受 `flutter analyze` 涵蓋；Dart 部分本票未觸碰，跳過）。
- Swift 端無獨立 lint 工具，依 `scripts/run-tests.sh` 全量測試作為品質閘門，見下方 Test Results。
- 命名與註解依 CLAUDE.md 常數集中規範：`layerBounds` 無新增魔法數字，沿用既有 `CursorLocatorEffectConstants`。

### Phase 4 重構評估

- **重構需要**：否。改動範圍限定在單一資料結構補欄位與其消費端收斂，無新增技術債務。
- **技術債務**：無新增；反而消除了 W3-001 Phase 4 審查標記的既有技術債務（Spotlight 反查宿主圖層、BorderFlash 隱式 autoresizing 觸發時機不確定性）。
- **程式碼品質**：A（三處 bounds 跟隨策略收斂為單一來源，符合 `CursorLocatorEffectFrame` doc comment 明載的設計目的；與 1.4.0-W3-022 的 `synchronizeSublayerContentsScale` 為同一設計主張的另一半——宿主下發取代 sublayer 反問宿主）。
- **結論**：無需進一步重構。
