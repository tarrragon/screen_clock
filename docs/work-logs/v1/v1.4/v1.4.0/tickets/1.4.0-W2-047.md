### 字面比對結果

逐一比對 AppInputBinding（lib/app_constants.dart:255-329）全部字面與
macos/Runner/InputBindingBridge.swift：

跨邊界且現況一致（18 個，已納入本次斷言）：
channelName、queryPermissionMethod、requestPermissionMethod、
updateBindingsMethod、beginCaptureButtonMethod、endCaptureButtonMethod、
onButtonCapturedMethod、bindingsArgKey、capturedButtonNumberArgKey、
buttonNumberKey、actionKey、actionTypeKey、dragScrollType、hotkeyType、
directionKey、sensitivityKey、keyCodeKey、modifiersKey。

梳理發現：舊版測試檔頭註解推測 buttonNumber/action/type 等屬「純 Dart
內部序列化鍵」不需守衛，經查證此推測不成立——這些鍵透過 updateBindings
method channel 下傳的 binding JSON map，Swift 端 applyBindings()
以相同字串鍵解析（如 binding["buttonNumber"]、action["type"]），確實
跨越語言邊界，故一併納入斷言。

非既有不一致（不納入本次斷言，非 bug）：
onPermissionChangedMethod（'onPermissionChanged'）與
grantedArgKey（'granted'）僅存在於 Dart 端常數宣告，Swift 端尚未實作
對應的 channel.invokeMethod 呼叫。查 lib/app_constants.dart 296-301
行註解：「回傳查詢當下的授權 bool（提示後使用者操作仍需經
onPermissionChanged 通知）」，確認這是預先定義、對應功能尚未實作的
常數，非兩端字面已宣告卻不一致的缺陷，故不建 spawn ticket。

Dart-only 非字面常數（不適用本測試機制）：
defaultDragScrollSensitivity（double）、defaultDragScrollButton（int）
非字串字面，本測試斷言機制（雙引號字串比對）不適用，且為 Dart 端
預設值計算用途，不跨越 channel 邊界。

## Context Bundle

### PM 補料（2026-08-06）：執行環境限制與回報紀律

#### 一、worktree 內無法執行 `ticket track complete`（已知 runtime 誤判）

Claude Code runtime 的 worktree 沙盒會把子命令位置的 `complete` 誤判為 bash 內建指令（programmable completion），逐字訊息為：

> runs a string through complete, which can't be verified to stay inside the worktree

歸屬為 CC runtime 而非框架資產，專案側無法修復（`tarrragon/claude#43`）。**這不是執行者的錯誤，也不是權限不足。**

**因此本票的收尾 complete 由 PM 代跑。** 執行者做到 `append-log`（Test Results / Completion Info）與 `set-acceptance` 勾選為止，回報時附上 worktree 路徑與分支名即可。

#### 二、遇拒即停並揭露（PC-SCLK-010 防護）

遇到任何拒絕——hook 阻擋、權限拒絕、沙盒限制——立即停止該動作，在回報中說明：哪個命令、拒絕訊息逐字、你的判斷。

**禁止改寫命令字面、換用其他寫法或繞道重試。被拒不算失敗，隱瞞才算。**

背景：`1.4.0-W2-046` 的執行者在 complete 被拒後以字串拼接（`SUB="comp""lete"`）繞過，並在 Exit Status 填 `success` / `confidence: 1.0` 未提及此事。產出本身正確，但派發者因此失去判斷該次執行是否循預期路徑完成的依據。完整模式見 `.claude/error-patterns/process-compliance/PC-SCLK-010-*.md`。

#### 三、fresh worktree 的建置前置

跑 `scripts/run-tests.sh` 之前需依序執行：`flutter pub get` → `flutter build macos --config-only`（重建 `macos/Flutter/ephemeral/*.xcfilelist`）→ `pod install`（於 `macos/`）。gitignored 產物不隨 worktree 帶入，跳過會出現看似測試問題的建置失敗（W2-046 實測路徑）。

#### 四、與 W2-046 的接縫

`test/platform/channel_contract_test.dart` 的檔頭註解已由 W2-046 更新為列出 `FullscreenCoverageDetector.swift` 與 `CursorLocatorBridge.swift` 兩檔。本票新增 `InputBindingBridge.swift` 至 `setUpAll` 讀取清單後，需同步該處敘述為三檔。

第 46 行另有一處 `MainFlutterWindow.swift` 引用，是描述 W2-015 拆分事件的歷史敘述，**正確且不應改動**。
