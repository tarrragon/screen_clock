**C4 的可達性已實證**（PM 於主 repo 執行 dart 驗證）：`double.tryParse('NaN')` 回傳合法 `double.nan` 而非 null，故 `_asDouble` 會靜默接受損毀設定檔中的 `"NaN"`；`(NaN * 1000).round()` 與 `(Infinity * 1000).round()` 皆拋 `UnsupportedError`。完整路徑為：損毀或竄改的偏好設定檔 → `fromJson` 靜默接受 → 直到某次 `play()` 才拋出，且例外落在 catch 外。

**A 與 B 是兩件事，不可混為一談**（coupling 交叉查證的關鍵區分）：改用 `Duration` 後 NaN 症狀會消失（`Duration` 內部是整數微秒，建構不出 NaN），但根因——`fromJson` 完全不做值域檢查、min/max 常數零引用——不會消失，只是 crash 觸發點從 CursorLocator 內部搬到未來呼叫端的轉換那一行。值域檢查缺口另由 1.4.0-W2-010 處理。

**PM 註記**：本票 Context Bundle 要求「秒轉毫秒的換算點須明確命名或註解標示」，該要求方向有誤。linux 指出這是「註解在補設計的洞」——正因簽章收裸 double 才需要具名轉換函式，才需要六行註解解釋轉換函式為何具名，才需要一條測試釘住 `round()` 這個本不必存在的決策。若簽章依 SPEC 用 `Duration`，這一整串都不存在。PM 撰寫該 Context Bundle 時未比對 SPEC-008:277 的介面宣告。

正面確認（掃過無發現）：MethodChannel 建構子注入確實解除平台耦合，測試方向正確；Swift bridge 生命週期（強參考持有 + weak self closure）與既有兩個 bridge 同模式，無 retain cycle；例外處理雙 catch 皆 `developer.log(level: 900)` 符合 observability 規則 1；測試斷言符合 test-assertion-design D1-D5（無計時斷言、無 `DateTime.now()`、無未固定 seed）。coupling 另指出本票的 Swift 端 `private enum CursorLocatorChannel` 集中常數，比既有 FullscreenCoverageDetector 與 InputBindingBridge 的散落字面更嚴謹，是優於既有先例之處。

### 秒轉毫秒的換算點（本票的落實位置）

設定層以 double 秒儲存（SettingsModel.cursorLocatorEffectDurationSeconds），傳輸層以 int 毫秒傳遞（durationMsArgKey）。本票建立的 lib/platform/cursor_locator.dart 是兩者交界，換算須在此發生且有明確命名或註解標示——1.4.0-W1-011 實測 E3 確認單位變更無任何機械訊號，換算點若隱含在運算式中，日後修改者無從察覺。

主色調同理：設定層為 Color 物件，傳輸層為 ARGB int（tintArgbArgKey），轉換點須同樣明確。

骨架階段即使尚未真正傳送參數，也應把換算函式或轉換點的位置定出來，讓 1.4.0-W2-006 與 1.4.0-W3-001 有明確的填入位置。
