### 缺口 Ticket 建議與派發順序

依據 SPEC-008 架構決策（特效層為 Swift NSWindow + CALayer，熱鍵為 Dart hotkey_manager，兩者經 method channel 橋接），建議將缺口拆為以下實作票：

| 建議 ticket | 類型 | 覆蓋範圍 | 依賴 | 建議 Wave |
|------------|------|---------|------|----------|
| 全域熱鍵註冊與生命週期 | IMP / P0 | FR-01 + UC-06 06c 停用解除 + EX-06-01 | blockedBy W1-001（需 AppCursorLocator 常數與 SettingsModel 啟用開關） | W2 |
| Swift 特效層：螢幕判定 + 聚光燈 + 邊框 + 波紋 | IMP / P0 | FR-02 + FR-03 + FR-04 + FR-05 + UC-06 主成功步驟 2-5 + 06a + 06b + 06d + EX-06-02 + EX-06-03 | blockedBy W1-001（需 channel 骨架）+ 熱鍵票（需觸發入口） | W2/W3 |
| 設定面板滑鼠定位器區塊 | IMP / P1 | FR-06 設定面板 UI + UC-06 06c 設定面板停用 | blockedBy W1-001（需 SettingsModel 三欄位）；可與特效層並行 | W3/W4 |

**依賴關係**：W1-001（基礎建設） -> 熱鍵票 + 特效層票（可並行） -> 設定面板票（可與特效層並行）。

**備註**：特效層票範圍較大（涵蓋 4 個 FR），PM 可視認知負擔評估進一步拆分（如螢幕判定 + 視窗管理為一票，三種視覺特效為一票）。此處以 SPEC-008 架構決策「Swift 側閉環」為依據合併，因三種特效共用同一 NSWindow 與 CVDisplayLink，拆開反增跨票同步成本。
