## Context Bundle

### 任務定位

1.4.0-W1-001 Phase 4 多視角評估（五視角，情境 B）的本輪執行項。評估共產出 16 項發現，本票執行其中四項（A/B/G/J），其餘 12 項已建票追蹤（1.4.0-W2-007 至 W2-015）。完整評估結論見 1.4.0-W1-001.1 至 .4 各自 Solution 的「Phase 4 審查證據」章節，其中 .3 那份含 A 與 B 的完整論證與實證。

### 四項修正明細

**A. `play()` 簽章改為 `Duration`**（`lib/platform/cursor_locator.dart`）

SPEC-008:277 明訂 `Future<void> play({required Duration duration, required Color tint})`，實作為 `double durationSeconds`。linux 與 coupling 交叉查證判定這是介面層級的單位洩漏：platform 橋接層的公開介面被迫知道「SettingsModel 用雙精度秒儲存」這個設定層慣例。改回後 `_durationSecondsToMs` 移除，內部改用 `duration.inMilliseconds`，秒的概念不再進入 platform 層。

類別 doc 的六行單位換算註解（`:25-30`）隨之刪減至必要範圍。linux 判定那六行是「註解在補設計的洞」——正因簽章收裸 double 才需要具名轉換函式，才需要註解解釋轉換函式為何具名，才需要一條測試釘住 `round()` 這個本不必存在的決策。型別改對後整串都不需要。

時效性：production 目前零呼叫端（唯一呼叫點是測試），1.4.0-W2-006 接上 caller 後此修改成本顯著上升。

**B. 轉換呼叫移入 try 區塊**（同檔）

`_tintToArgb` 與原 `_durationSecondsToMs` 呼叫位於 `:35-36`，try 從 `:39` 才開始。PM 已於主 repo 實證：`double.tryParse('NaN')` 回傳合法 `double.nan` 而非 null，故 `_asDouble` 會靜默接受損毀設定檔中的 `"NaN"`；`(NaN * 1000).round()` 與 `(Infinity * 1000).round()` 皆拋 `UnsupportedError`。完整路徑為損毀或竄改的偏好設定檔 → `fromJson` 靜默接受 → 直到某次 `play()` 才拋出，例外落在 catch 外、零日誌，違反 observability-rules 規則 1。

補一筆對應測試。注意 A 改用 `Duration` 後 NaN 症狀會消失（`Duration` 內部是整數微秒，建構不出 NaN），但 B 仍須做——`_tintToArgb` 的轉換仍在 try 外，且此修正的價值是「轉換期例外走既有 catch-log 路徑」這個結構，不繫於特定輸入。

**G. `_colorToInt` 改用 `toARGB32()`**（`lib/models/settings_model.dart:287-293`）

手刻位移用 `& 0xff` 迴繞，SDK `toARGB32()` 用 `clamp(0, 255)` 飽和（redundancy 讀 SDK 原始碼 painting.dart:217-219,255-260 確認，兩式差異僅此一處，乘數與捨入完全相同）。實測分歧點：component 1.2 在 SDK 下為 255、手刻版為 50（迴繞把飽和誤差變成反相）。

目前 app 內所有 Color 來源皆為 `const Color(0xFF...)` 或被 slider 夾在 0-1，故所有可觸及輸入下位元相同，既有 prefs 不需遷移。但迴繞在超色域（如未來改用 NSColorPanel 取得 Display P3 色）時是錯誤行為。此修正同時讓 `cursorLocatorPrimaryColor` 的持久化路徑與傳輸路徑收斂至同一實作。

**J. 改 SPEC 而非改 code**（`docs/spec/user-experience/SPEC-008-cursor-locator.md:274-278`）

SPEC 宣告 `abstract class CursorLocator`，實作用 concrete class。linux 判定實作端做出了比規格更好的判斷——建構子注入 `MethodChannel` 已完成可測試性（`cursor_locator_test.dart:22` 印證），不需為永遠只有一個實作的類多開抽象層。更新 SPEC 的宣告與簽章（與 A 的 `Duration` 同一輪對齊），於 Solution 記錄「改 SPEC 不改 code」的理由。
