### 要解決的問題

本專案有三個 method channel 橋接檔，它們在「呼叫原生端並處理失敗」這件事上的處理方式不一致，且其中兩者是同一段邏輯的兩份實作：

| 檔案 | 失敗處理骨架 | 日誌機制 |
|------|------------|---------|
| `lib/platform/cursor_locator.dart` | try / catch PlatformException / catch MissingPluginException / catch UnsupportedError / 記錄後吞掉 | `developer.log` + `_tag`（符合 observability-rules 規則 2） |
| `lib/input/input_binding_channel.dart` | 同一骨架（`_invoke`，前三個 catch 相同） | `debugPrint`（**違反** observability-rules 規則 2），且 `[input-binding]` 前綴字面重複寫在 7 處呼叫點 |
| `lib/platform/fullscreen_detector.dart` | 監聽方向為主，無 invoke 骨架 | `debugPrint`（**違反**同一規則） |

兩個問題疊在一起：邏輯重複，以及既有的日誌規則違規。Phase 4 的 coupling 視角指出，處理前者的動作會自然涵蓋後者——抽取共用實作時必然要決定用哪個日誌機制，而合規的選擇只有一個。

成本累積：1.4.0-W2-006 將為 cursor locator 新增 `stop` / `updateConfig` 等方法，維持現狀則每新增一個方法就複製一次骨架。

### 判準

本票要達成的性質：

- **重複消除**：try / catch / 記錄 / 吞例外這組骨架在專案中只有一份實作，各呼叫點的差異僅限於必要參數（如日誌標籤）
- **日誌合規**：三個檔案皆使用專案統一日誌工具，無 `debugPrint` 殘留（observability-rules 規則 2）
- **前綴單一來源**：`input_binding_channel.dart` 重複 7 處的前綴字面收斂
- **例外語意不變**：兩側既有的例外路徑測試維持綠燈，本票不改變「記錄後吞掉不外洩」這個對呼叫端的契約

### 邊界與相鄰票的關係

- **不改變例外處理契約**：是否改讓呼叫端能感知失敗（例如回傳成功旗標、或讓 Swift 端回 `FlutterError`），屬 1.4.0-W2-016 的評估範圍。本票只做結構收斂，維持現行「吞掉不外洩」語意。抽取時請讓共用實作保有日後擴充的空間，但不要在本票實作那個擴充
