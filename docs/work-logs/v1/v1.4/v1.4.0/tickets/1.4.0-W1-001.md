## Context Bundle

### 任務定位

v1.4.0 滑鼠定位器的共同前置。四張後續實作票依賴本票定案的介面：1.4.0-W2-005（全域熱鍵，需啟用開關與常數）、1.4.0-W2-006（特效層視窗管理，需 channel 骨架）、1.4.0-W3-001（視覺特效，需動畫參數常數）、1.4.0-W3-002（設定面板，需三個欄位）。介面反覆的成本會乘以四，故本票的契約須一次定案。

| 來源 | 提供什麼 |

| docs/spec/data-management/SPEC-009-settings-storage-data-contract.md v1.1 | 資料契約的權威來源。A 區 INV-01 至 INV-09、A.1 演進表（含 v4 條目）、A.3 治理條款 G-01 至 G-04 |

SPEC-008 與 SPEC-009 對同一欄位的描述若有出入，以 SPEC-009 為準（資料契約是欄位定義的權威，SPEC-008 是功能需求）。

### INV-03 約束（本票最須注意的一條）

SPEC-009 將 INV-03（只加欄、不改型別、不刪欄）標為「本契約最脆弱的一條，無機械強制訊號」。schema 4 是 INV-03 生效後的第一次升版，本票的加欄方式即是該不變式的示範案例。

具體要求：

- 只新增欄位，不修改任何既有欄位的名稱、型別或語意
- 不移除任何既有欄位（含已無用者）
- schemaVersion 由 3 升為 4，並於 SPEC-009 A.1 演進表新增對應列（依 G-03：新增一般設定欄位必須提升版本號並登錄演進表）

1.4.0-W1-015 已建立 v1/v2/v3-early/v3-late 四組 golden fixture 迴歸測試（本票 blockedBy 該票）。若本票的改動違反 INV-03，那組測試會轉紅——這是方案 C 設計的機械訊號，不可為了讓測試通過而修改 fixture 內容。

### W1-011 的三項實作註記（已納入 acceptance）

| 註記 | 理由 |
|------|------|
| 時長欄位名含單位（如 cursorEffectDurationMs） | W1-011 實測 E3：語意或單位變更現行機制完全無法偵測（birthDate 若由毫秒改秒，946684800 會被讀成 1970-01-12 並在下次存檔永久寫入錯誤值）。欄位名帶單位是唯一能在 code review 階段攔截此類變更的訊號 |
| 主色調以 ARGB int 經 _asColor 存取 | 與既有欄位的處理方式一致；Color 物件直接序列化會在 Flutter 版本升級時產生格式風險 |
| round-trip 測試涵蓋 v3 兩種形態 | v3-early 與 v3-late 的 schemaVersion 皆為 3，差異僅在 bindingsSeeded 鍵是否存在。只測其一會漏掉 _migrateBindingSeed 的觸發分支 |

### schema 4 三欄位的定義來源

SPEC-009 A.1 的 v4 條目已記錄語意、型別與預設值，但來源標註為 SPEC-008 FR-06（規格）而非 code——因為當時尚未實作。本票是把該規劃落為實作。

實作後須回頭確認 SPEC-009 A.1 的 v4 條目與實際 code 一致；若有出入，以實作為準並更新 SPEC-009（於 Solution 記錄差異與更新內容）。

### 執行約束

- 不修改既有欄位（INV-03）
- 不修改 1.4.0-W1-015 建立的 fixture 內容
