## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

（選填：修復方式概述、修改的檔案和驗證方式）

三個 renderer 各於 attach/detach 補一行 NSLog（debug 級，前綴 `[cursor-locator]` 沿用控制器層慣例），內容含 renderer 型別名與 layer bounds：

- `CursorLocatorSpotlightRenderer`：attach 用 `layer.bounds`；detach 用移除前快取的 `dimLayer?.bounds`（先讀後 nil，避免記錄到已清空狀態）。
- `CursorLocatorBorderFlashRenderer`：同上模式，用 `borderLayer?.bounds`。
- `CursorLocatorRippleRenderer`：無單一持有圖層，attach 用傳入的 `layer.bounds`；detach 用 `ringLayers.first?.superlayer?.bounds`（移除前讀取，因移除後 superlayer 為 nil）。

render 逐幀路徑（三檔的 `render(_:)`）未加任何日誌，符合 acceptance 第 3 項與 how.strategy「60Hz 會淹沒日誌」的理由。

### 自檢結果

- 三個 renderer 的 attach/detach 各有一行日誌，含型別名字面字串與 bounds 值：符合。
- 日誌前綴 `[cursor-locator]` 與 MainFlutterWindow.swift / CursorLocatorEffectWindow.swift 既有慣例一致：符合。
- 未修改 CursorLocatorEffectWindow.swift（本票約束）：符合，僅動三個 renderer 檔。
- Phase 4 結論：改動為三處對稱的日誌插入，無新增分支或狀態，無需重構；三檔既有的 detach 冪等測試（`testDetachTwice_isIdempotent` 等）覆蓋了日誌插入後的行為不變性。品質評級 A。
