### Phase 3a 對本子票的關鍵約束

以下三點在母票 §三有完整說明，此處摘要以免遺漏：

1. **步驟 4 必須先跑單一 smoke 案例**：只寫一個必然通過的案例並實際執行，確認命令輸出「1 個案例通過」才算執行路徑就緒。理由是 15 案例一次寫完再跑，首次失敗時無法分辨是接線問題還是判定邏輯問題。
2. **涵蓋判定直接用平台矩形型別的「包含點」語意**（`minX <= x < maxX`、`minY <= y < maxY`），不自行以四則運算重寫比較式——自行重寫是邊界歸屬出錯的主要來源。
3. **判定函式簽章不得出現任何平台螢幕型別或游標取樣來源**，取樣責任在呼叫端。

### 座標系提醒（PC-SCLK-006 已在本 ticket 二度發生）

AppKit 全域座標原點在主螢幕左下角、**y 軸向上為正**。第二螢幕置於主螢幕左方時 x 為負、置於**下方**時 y 為負；置於上方時 y 為正。母票 Phase 2 的 fixture 已依此更正，實作時勿依直覺推斷。
