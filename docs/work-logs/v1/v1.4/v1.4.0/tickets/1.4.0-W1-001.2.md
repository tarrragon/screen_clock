SettingsModel（lib/models/settings_model.dart）新增游標定位器三欄位：`cursorLocatorEnabled`（bool，預設 true）、`cursorLocatorEffectDurationSeconds`（double 秒，預設 1.5，值域 0.5–3.0）、`cursorLocatorPrimaryColor`（Color ARGB32 int，預設 `Color(0xFF2196F3)`）。schemaVersion 由 3 升為 4。三欄位接線至建構子、`defaults()`、`fromJson()`（缺欄補預設值不拋例外）、`toJson()`、`copyWith()`、`==`/`hashCode`，未修改任何既有欄位（INV-03）。

**命名決策**：欄位名沿用 test/models/settings_model_test.dart 既有 v4 骨架 fixture 的佔位鍵名（`cursorLocatorEnabled` / `cursorLocatorEffectDurationSeconds` / `cursorLocatorPrimaryColor`），Dart 欄位名與 JSON 鍵名一致，未經 AppSettingsKeys 間接層（與 fontSize 等純量欄位慣例相同）。

**與規劃的偏離（主色調預設值實作細節）**：SPEC-009 A.1 原描述「主色調預設系統藍」未指定實作型別。實測發現若直接用 `Colors.blue`（Flutter `MaterialColor` 子型別）作預設值，round-trip 後 `fromJson(toJson(model)) == model` 斷言失敗——`MaterialColor` 與由 `Color(argb)` 建構的 `Color` 比較 `==` 時因 `runtimeType` 不同而不相等，即使 ARGB 分量完全一致。改採同色值的純 `Color(0xFF2196F3)` 常數解決。已回填 SPEC-009 A.1 記錄此決策理由。

**app_constants.dart 常數登錄延後**：依 Context Bundle 執行約束本票不得觸碰 lib/app_constants.dart（屬平行進行的 1.4.0-W1-001.1）。`cursorLocatorPrimaryColor` 的預設值以裸 `Color(0xFF2196F3)` 表示，觸發 Presence Guard hook，已於命中行加 `// color-exempt` 並附理由註解說明延後登錄由 W1-001.1 或後續 DOC 票補上 AppColors 常數。

**測試涵蓋**：test/models/settings_model_test.dart 新增/更新測試：schemaVersion 斷言改為 4；1.4.0-W1-015 建立的 v1/v2/v3-early/v3-late 四組 golden fixture 內容未修改（全綠驗證 INV-03 未被破壞）；v4 骨架 fixture 由佔位鍵名改為實際鍵名並補三欄位逐一斷言；新增「cursor locator fields」測試群組涵蓋 defaults、v3-early/v3-late 缺欄補預設值、round-trip、copyWith、equality/hashCode。

**SPEC-009 回填**：A.1 主表欄位集由 v3 更新為 v4（新增三列）；版本演進表 v4 列由「規劃中（SPEC-008 FR-06 規格）」轉為「已落地（1.4.0-W1-001.2，實際欄位名）」；B.3 v4 演進列更新為已確認；新增變更歷史 1.2 版記錄；frontmatter updated/version 同步更新。

### INV-03 約束（本票最須注意的一條）

SPEC-009 將 INV-03（只加欄、不改型別、不刪欄）標為「本契約最脆弱的一條，無機械強制訊號」。schema 4 是 INV-03 生效後的第一次升版，本票的加欄方式即是該不變式的示範案例。

具體要求：

- 只新增欄位，不修改任何既有欄位的名稱、型別或語意
- 不移除任何既有欄位（含已無用者）
- schemaVersion 由 3 升為 4，並於 SPEC-009 A.1 演進表新增對應列（依 G-03：新增一般設定欄位必須提升版本號並登錄演進表）

1.4.0-W1-015 已建立 v1/v2/v3-early/v3-late 四組 golden fixture 迴歸測試。若本票的改動違反 INV-03，那組測試會轉紅——這是方案 C 設計的機械訊號，不可為了讓測試通過而修改 fixture 內容。

### schemaVersion 的實際角色（1.4.0-W1-011 實測 E1）

fromJson() 完全不讀取 schemaVersion，版本相容全靠「欄位缺失取預設值」達成。schemaVersion 是單向的稽核標記：只在 toJson() 寫出，從不參與解析。因此本票不需新增版本分支 migration，沿用加欄加預設值策略即可（SPEC-009 A.1 v4 條目已確認此策略對 v4 成立）。

### W1-011 的三項實作註記

| 註記 | 理由 |
|------|------|
| 時長欄位名含單位（如 cursorEffectDurationMs） | W1-011 實測 E3：語意或單位變更現行機制完全無法偵測（值被靜默誤讀並在下次存檔永久寫入錯誤值）。欄位名帶單位是唯一能在 code review 階段攔截此類變更的訊號。命名須與 1.4.0-W1-001.1 的常數慣例一致 |
| 主色調以 ARGB int 經 _asColor 存取 | 與既有欄位處理方式一致；Color 物件直接序列化會在 Flutter 版本升級時產生格式風險 |
| round-trip 測試涵蓋 v3 兩種形態 | v3-early 與 v3-late 的 schemaVersion 皆為 3，差異僅在 bindingsSeeded 鍵是否存在。只測其一會漏掉 _migrateBindingSeed 的觸發分支 |
