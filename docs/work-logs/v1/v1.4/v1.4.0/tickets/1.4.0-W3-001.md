### 三處預期衝突與解法

PM 已實測 `.4` 對含 `.2` 的 main 之衝突面，三處全部落在派發前預告的位置：

**1. `MainFlutterWindow.swift` 的 renderers 陣列**

三張各自把自己那項加進 `CursorLocatorCompositeRenderer(renderers: [...])`。
陣列順序即 sublayer 疊加順序（先加者在下），**PM 指定 z-order 為**：

```
[CursorLocatorSpotlightRenderer(), CursorLocatorRippleRenderer(), CursorLocatorBorderFlashRenderer()]
```

理由：聚光燈是覆蓋全螢幕的壓暗遮罩，必須墊底，否則會蓋住波紋與邊框；波紋在游標處疊於壓暗之上；邊框位於最外層不受壓暗影響。此順序無法由任一子票單獨決定——三個代理人各在獨立 worktree，都只看得到空陣列。

**2. `CursorLocatorEffectConstants`（`CursorLocatorEffectWindow.swift`）**

三張各新增自己的常數區塊（`.2` 五個、`.3` 三個、`.4` 若干）。三方並列附加即可，
不刪除任何一方的常數，保持各自的 doc comment。

**3. `macos/Runner.xcodeproj/project.pbxproj`**

三張各註冊兩個新檔（renderer + 測試）到對應 target。各自的 UUID 前綴不同
（`.2` 用 `5C1A0B0012D34E5A9F0A00xx`、`.4` 用 `RIP1E`/`RIP2E`），不會撞號，
但同區塊相鄰行會衝突。**此檔解錯會使 Xcode 專案無法開啟**，須逐區塊確認
三方條目都在（PBXBuildFile / PBXFileReference / PBXGroup children / PBXSourcesBuildPhase files）。

### 測試基準校正

`.3` 與 `.4` 兩張獨立實測 main 的 XCTest baseline 為 **85**（非 ticket 早期記載的 84）。
PM 亦以逐檔 `grep -c "func test"` 加總複驗得 85。

三張各自在自己的 worktree 實測：`.2` → 99、`.3` → 101、`.4` → 97。三者的 base 都只含
自己那一張，故整併後的總數**不是**任一數字，須實跑確認。預期為 85 + 15 + 16 + 12 = 128，
但這是相加推算，以 `scripts/run-tests.sh` 實跑結果為準。

### worktree 前置（三張都遇到）

而失敗，屬 build 層問題非程式碼問題。執行 `flutter pub get` +
`flutter build macos --debug --config-only` 後恢復。`macos/Pods/` 已被 gitignore，不進 commit。

### 整併後必須確認的事

- 三種特效的常數無命名碰撞（各自前綴 `spotlight` / `flash` / `ripple`）
