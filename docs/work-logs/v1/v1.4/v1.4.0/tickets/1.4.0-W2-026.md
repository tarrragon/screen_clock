### 範圍收斂（PM 依 1.4.0-W2-006 Phase 3a 的 N-1 裁定回寫，2026-08-01）

W2-006 Phase 3a 裁定採納「抽出錯誤碼純對應函式」，該工作落於 `1.4.0-W2-006.2`，本票範圍相應收斂。

**已由 1.4.0-W2-006.2 完成、本票不再重做**：

- 建立 `CursorLocatorError` → `FlutterError` 的純對應函式（落於 `macos/Runner/CursorLocatorErrorMapping.swift`）
- `E_CL_SCREEN` / `E_CL_WINDOW` 兩個錯誤碼字面已於該檔以專用列舉承載，非散落字面
- 對應函式已有測試覆蓋（RunnerTests 群組 E：T2.E-05 / T2.E-06，以字串字面逐字斷言）

**本票保留範圍**：

1. **命名慣例統一**：既有 `CursorLocatorBridge` 的 `invalid_arguments`（小寫蛇底線）與 SPEC-008 的 `E_CL_*`（大寫底線前綴）兩套慣例共存，須裁定單一慣例並改寫既有碼。本票不得逕改 `E_CL_*` 兩碼的字面——已由 SPEC-008 定義且已有測試鎖定
2. **Dart 側常數集中**：`lib/app_constants.dart` 的 `AppCursorLocator` 補上錯誤碼常數，並與 Swift 側列舉建立逐項一致的註解對照（現況 `grep -rn E_CL lib/` 零命中）
3. **跨 bridge 盤點**：settings bridge 等其他 bridge 的錯誤碼一併納入同一慣例
4. **日誌前綴字面**（`[cursor-locator]` 等）的常數化，與錯誤碼同屬「Swift 側字面集中」議題

**執行時的必要驗證**：改動錯誤碼字面會使 RunnerTests 群組 E 紅燈，屬預期。若裁定改名 `E_CL_*`，須同步改 SPEC-008、UC-06、測試字面三處，缺一即為規格漂移。

**與 1.4.0-W2-035 的邊界**：本票是「常數集中」（把散落字面收攏到單一宣告處），W2-035 是「持續驗證兩側一致」（機械檢查 Dart 與 Swift 宣告不漂移）。W2-035 已標 `blockedBy: 1.4.0-W2-026`。
