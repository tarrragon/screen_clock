### dispatch-readiness 閾值 1 的 PM 覆核結論（不需再拆）

`ticket track dispatch-readiness 1.4.0-W3-001.4` 對閾值 1 回報 FAIL（acceptance 6 > 4）。
PM 依 `references/track-command.md` 註明的「閾值 1 以 acceptance 條目近似職責數，
含驗證類條目時可能高估，WARN/FAIL 應手動覆核」執行覆核，結論為**不需再拆**。

理由：六條 acceptance 全部隸屬同一功能職責（波紋擴散繪製），是 SPEC-008 FR-05
約束條件細所致，非六個獨立職責：

| acceptance | 性質 |
|-----------|------|
| 三圈同心圓向外擴散 | 形態約束 |
| 半徑 20→180 px、透明度 100%→0%、歷時 500 ms | 單圈時間曲線 |
| 三圈發出間隔 150 ms | 多圈時序 |
| 淡出完整無殘留 | 收尾狀態驗證 |
| 圓心跟隨游標且消費 .1 共用取樣 | 資料來源約束（與 FR-03 同步的前提） |
| 顏色取自 request.tint | 資料來源約束 |

「功能職責數 > 2 須拆分」未觸發。

接手者若再次看到此 FAIL，依本節結論直接執行，不需重複拆分評估。
### 1.4.0-W3-001.1 已提供的基礎（不要重造）

| 提供物 | 用途 |
|--------|------|
| `CursorLocatorEffectRendering` protocol | 你的 renderer 實作此協定：`attach(to:tint:duration:)` / `render(_:)` / `detach()` |
| `CursorLocatorEffectFrame` | 每幀交付的值型別：`progress`（0..1）/ `elapsed` / `duration` / `cursorPointInLayer` / `tint` |
| `CursorLocatorEffectConstants` | 特效數值的單一集中處，你的半徑範圍與時序加在此 |
| `CursorLocatorCompositeRenderer` | 廣播器；production 目前傳 `renderers: []`，你把自己的 renderer 加進去 |

`cursorPointInLayer` 已是轉換到 `contentLayer` 座標系的點（左下原點），每幀只取樣一次且與 `.2` 聚光燈共用——**不要自行呼叫 `NSEvent.mouseLocation`**。SPEC-008 FR-05 明文要求「與 FR-03 共用同一組游標位置取樣」，各自取樣會使波紋跑出亮區外，且只在快速移動時偶發。

三圈的 150 ms 間隔與單圈 500 ms 生命期需要**絕對時間軸**：用 `CursorLocatorEffectFrame.elapsed`（自首幀起算秒數），不必從 `progress * duration` 反推。

`contentLayer` 的幾何、`contentsScale`、隱含動畫停用已由 `1.4.0-W3-018` 的 `LayerHostingView` 處理，你不需重複處理。

### SPEC-008 FR-05 的數值約束

- 單圈半徑由 20 px 擴散至 180 px，透明度由 100% 淡至 0%，歷時 500 ms
- 三圈的發出間隔 150 ms（即第 2 圈於 t=150ms 發出、第 3 圈於 t=300ms）
- 圓心跟隨游標，與 FR-03 共用同一組取樣
- 顏色取自使用者設定的主色調（`CursorLocatorEffectFrame.tint`，非硬編碼）

驗收標準（SPEC 原文）：觸發後游標位置出現三圈向外擴散的波紋；波紋淡出完整無殘留圖形；播放期間移動游標，波紋圓心跟隨。

「圓心跟隨」有一個 SPEC 未言明的設計點：已發出的圈是否跟著游標移動，或釘在發出當下的位置。前者三圈永遠同心、後者會拖出軌跡。請擇一並在 Solution 記錄理由——FR-05 原文「圓心跟隨游標」讀來偏向前者，但實機觀感需 `1.4.0-W3-006` 確認。

最後一圈於 t=300ms 發出、500 ms 後淡盡，故波紋總長約 800 ms。若 duration 短於此需決定行為（截斷或壓縮），請在 Solution 記錄取捨——SPEC 未規定此邊界。
