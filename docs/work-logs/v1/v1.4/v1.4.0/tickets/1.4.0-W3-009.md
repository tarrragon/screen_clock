### 與 1.4.0-W3-012 的執行順序（PM 註記，來源 1.4.0-W3-007 Phase 4）

本票 acceptance 第 4 條要求「generation 在 reset 不遞增的設計未被更動」。該條款的意圖是防止本票的重構破壞既有世代機制，適用範圍僅限本票自身。

1.4.0-W3-007 的 Phase 4 審查（linux 視角）之後發現 generation 的語意本身值得重新設計——世代序號區辨的是 session 之間而非 playing 對 idle，改為 allocator 加 epoch 結構可消除 endPlayback 的遞增步驟與一條隱性人工同步。該重整已建為 1.4.0-W3-012，並標記 blockedBy 本票。

執行順序：本票先，W3-012 後。倒置會使本票的驗收條件與 W3-012 的目標直接抵觸。執行本票時無需為 W3-012 預留任何結構，維持 generation 現狀即可。

### 當前量測基準（執行者應自行複驗，非採信本節）

handleFrame 現為 42 行（W3-007 前為 46 行），區域變數 10 個：currentSession / snapshot / cursorLocation / resolution / start / elapsed / fadeDuration / fadeStart / remaining / alpha。acceptance 要求區域變數降至 5 以下，故至少需外提兩組（前置三行與淡出計算）才可能達標。

### 風險預測（可驗證形式）

- 若 reset 搬遷區塊併入 updateTargetScreenIfNeeded 時未保留「僅在 frame 相異時才 retarget」的條件，跨螢幕相關測試（T2.D-03 / 04 / 05）會紅燈。
- 若 scheduleDeadline 抽取時把世代取得寫進函式內部而非由呼叫端傳入，startNewPlayback 遞增而 reset 不遞增的差異會被抹平，1.4.0-W2-041 建立的世代守護測試會紅燈。
- 若淡出純函式的邊界處理與原地實作不一致（clamp 範圍、fadeDuration 為 0 時的短路），淡出相關斷言會紅燈。

以上三項皆為可由測試判定的預測，非關於程式碼性質的斷言。執行時若與預測不符，以實測為準並記錄差異。
