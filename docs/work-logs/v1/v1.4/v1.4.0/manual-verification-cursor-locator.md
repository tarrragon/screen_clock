# 游標定位特效實機驗證清單（M-1 ~ M-8）

**來源**：`1.4.0-W2-006` Phase 2 測試設計 §七
**適用票**：`1.4.0-W2-006.2.2` acceptance 3（階段一）、`1.4.0-W3-001` 驗收前置（階段二）

---

## 分兩階段執行的原因

`1.4.0-W2-006` 的範圍是**螢幕判定與視窗生命週期**，明確不含三種視覺特效的繪製（留 `1.4.0-W3-001`）。因此目前 production surface 建立的是一個透明的空視窗：

```swift
hostView = NSView(frame: ...)      // 空 view，無繪製內容
window.backgroundColor = .clear
window.isOpaque = false
```

視窗會正確定位、正確跟隨、正確釋放，但畫面上看不見任何東西。

Phase 2 設計本清單時，判準寫的是「特效顯示於全螢幕內容**之上**，未被遮蔽」——該措辭隱含「有東西可看」的前提，與本 group 的範圍界定對不上。兩份文件各自正確，交叉後才顯現落差。

| 階段 | 涵蓋 | 執行時機 |
|------|------|---------|
| **階段一：行為面** | 視窗層級與焦點行為、資源釋放、日誌 | `1.4.0-W2-006.2.2` 收尾前（現在） |
| **階段二：視覺面** | 特效可見性、跟隨動態、疊加、淡出 | `1.4.0-W3-001` 完成後 |

階段一已足以證實視窗層級（`.screenSaver`）與 `orderFrontRegardless` 的不搶焦點策略是否成立——這兩者正是 UC-06 場景 06d 的核心風險，且與繪製無關。

## 階段一：現在可驗

### M-1　原生全螢幕（綠燈鈕）

**操作**

1. 於螢幕 A 開啟任一 app（如 Safari），點左上綠燈鈕進入原生全螢幕
2. 游標移至螢幕 A 該全螢幕 Space 內
3. 按下定位熱鍵

**通過判準**

- [ ] 全螢幕 app **未退出**全螢幕、未失去焦點
- [ ] 特效期間仍可操作該 app（打字或捲動有反應）

> 這兩條驗證的是 `orderFrontRegardless()` 而非 `makeKeyAndOrderFront()` 的選擇是否正確。Phase 1 §2.5 明列後者「於全螢幕播放中觸發熱鍵會導致退出全螢幕」，是本階段最關鍵的風險項。

### M-2　假全螢幕影片

**操作**

1. 於螢幕 A 播放影片並進入播放器全螢幕模式（YouTube 網頁全螢幕，或 IINA / QuickTime 的無邊框全螢幕）
2. 游標移至螢幕 A
3. 按下定位熱鍵

**通過判準**

- [ ] 影片**未暫停**、播放控制列未被觸發
- [ ] 特效期間影片持續播放
- [ ] 特效結束後影片仍為全螢幕

### M-3　簡報播放

**操作**

1. 於螢幕 A 以 Keynote 或 PowerPoint 進入簡報播放模式
2. 游標移至螢幕 A
3. 按下定位熱鍵

**通過判準**

- [ ] 簡報**未跳頁、未退出**播放模式
- [ ] 特效結束後簡報仍在原頁

### M-7　十次觸發無殘留

**操作**

1. 完整觸發並等待結束，重複十次
2. 觀察 Activity Monitor 的 window 數與記憶體

**通過判準**

- [ ] 無殘留視窗
- [ ] 記憶體無單調上升

> 此項為**輔證非主證**。無洩漏的主證是 T2.C-07 的雙訊號斷言（`close` 計數 + `weak` 為 nil），已於 XCTest 通過。肉眼觀察無法排除「視窗已隱藏但未釋放」，故不可反過來以此項通過推翻主證，也不可因此項可疑就否定主證。

### M-8　錯誤路徑日誌

**操作**

1. 觸發正常播放
2. 開啟 Console.app，過濾 process `screen_clock`

**通過判準**

- [ ] 正常路徑無 `E_CL_*` 錯誤
- [ ] 若曾發生退回 main，Console 可見對應 `E_CL_SCREEN` 訊息

> 第二條是 acceptance 6 日誌面的人工覆蓋。要刻意觸發退回 main，需把游標移到兩螢幕排列的間隙位置——若兩螢幕邊緣完全貼齊則無間隙，此時該條標為不適用即可。

## 階段二：需 `1.4.0-W3-001` 完成後

以下判準全部依賴可見的特效內容，在繪製未實作前無法判定真偽。

| 原編號 | 判準 |
|--------|------|
| M-1a | 特效顯示於全螢幕內容之上，未被遮蔽 |
| M-1d | 特效結束後畫面無殘留 |
| M-2a | 特效顯示於影片之上 |
| M-2d | 特效結束後無視覺殘留 |
| M-3a | 特效顯示於投影片之上 |
| M-4 | 跨螢幕跟隨：同一次播放內搬遷至螢幕 B、無閃爍、A 無殘影 |
| M-5 | 重複觸發：始終只有一層特效、無疊加變亮、每次從頭播放 |
| M-6 | 淡出與總時長：**聚光燈**約 3.0 秒（非 3.2 秒）、末段漸淡非瞬滅；邊框閃爍三次、波紋三圈（各自時長見下方說明） |

> M-6 的判準值得預先留意：時長若量到 3.2 秒，代表淡出被加在 duration 之後而非含在其內——逾時寬限（0.5 秒）是保險機制，不應影響正常路徑的總時長。
>
> **量測對象是聚光燈，不是三個效果各自的長度**（1.4.0-W3-006 實機驗證時的誤判來源）。三者依 SPEC-008 有不同的時長語意：

| 效果 | 規格時長 | 是否持續整個 duration |
|------|---------|---------------------|
| FR-03 聚光燈 | 無獨立時長，圓心持續跟隨游標 | 是——duration 由它界定，M-6 量的就是這個 |
| FR-04 邊框閃爍 | 閃爍三次，每次淡入淡出週期 200 ms，合計約 600 ms | 否，驗收標準明訂「閃爍三次後消失」 |
| FR-05 游標波紋 | 單圈 500 ms、三圈間隔 150 ms，合計約 800 ms | 否，三圈發完即結束 |

> **設計理由**：閃爍與波紋是事件式提示，回答「游標在哪個螢幕、哪個點」，訊息傳達完即應退場；聚光燈是狀態式環境，須維持到使用者實際找到游標。若觀察到閃爍或波紋撐滿整個 duration，那才是偏離規格。
>
> 閃爍 600 ms 與波紋 800 ms 難以肉眼計數，**次數**（三次／三圈）才是實機可判讀的判準；時長精度若需驗證，應錄影逐幀檢查而非現場計時。

## 記錄方式

**階段一**：逐項判定「通過 / 不通過 + 觀察摘要」，寫入 `1.4.0-W2-006.2.2` 的 Test Results。

M-1 / M-2 / M-3 任一不通過即代表 `.screenSaver` 層級或不搶焦點策略對該情境不足，屬 SPEC-008 決策 1 的修訂範圍，須依當時證據建票，**不在該票直接改 level**（Phase 1.5 收尾裁定）。

**階段二**：由承接票記錄，其結果同樣適用上述 SPEC-008 決策 1 的修訂條款。
