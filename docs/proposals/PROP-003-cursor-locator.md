# PROP-003: 多螢幕環境滑鼠定位器

## 需求來源

開發者個人需求：在多螢幕工作環境中經常無法立即判斷游標位於哪個螢幕，需來回移動指向裝置掃視各螢幕才能找到。screen_clock 已常駐系統，適合承載此功能而無須額外安裝工具。

## 問題描述

多螢幕使用者定位游標時面臨兩個層次的問題：

1. **不知道游標在哪個螢幕** — 需先確定螢幕，才談得上找到游標在螢幕中的位置
2. **知道螢幕後仍難以找到游標** — 游標尺寸小，在高解析度大螢幕上視覺對比不足

macOS 內建「搖晃滑鼠指標以尋找」僅放大游標，解決第 2 層而不解決第 1 層；使用者仍須先猜測游標所在螢幕。本提案以邊框閃爍標示螢幕、聚光燈與波紋標示位置，同時處理兩層問題。

| 影響項目 | 說明 |

| 模組 | 新增 `lib/platform/cursor_locator.dart`、`macos/Runner/CursorLocator/`；修改 `lib/main.dart`、`lib/models/settings_model.dart`、`lib/widgets/settings_panel.dart`、`lib/app_constants.dart` |
| 檔案 | `macos/Runner/MainFlutterWindow.swift`（註冊 channel） |

## 範圍界定

### 本提案要做的（In Scope）

- 全域鍵盤熱鍵（`Cmd + Option + L`）觸發，滑鼠與觸控板使用者皆適用
- 判定游標所在螢幕，於該螢幕播放定位特效
- 特效三組成：聚光燈壓暗、螢幕邊框閃爍、游標波紋擴散
- 特效播放期間游標跨螢幕時跟隨移動
- 設定面板提供啟用開關、特效時長、主色調三項設定，持久化

### 本提案不做的（Out of Scope）

- 變更系統游標本身的外觀或顏色 → macOS 無公開 API 可全域變更游標外觀，技術上不可行；改以疊加特效層達成等效視覺目的
- 擴充 SPEC-007 的 `MouseAction` 新增「定位游標」動作型別 → 綁定模型以實體側鍵為鍵，觸控板使用者無側鍵可綁，不滿足本提案的裝置涵蓋需求
- 修飾鍵 + 連點三下觸發 → 需在左鍵事件流上維護三連擊狀態機，風險與收益不成比例（詳 SPEC-008 決策 2）
- 熱鍵組合自訂 → 本版固定 `Cmd + Option + L`，開放自訂另立提案
- 特效樣式的完整自訂（波紋圈數、聚光燈半徑、邊框寬度）→ 本版僅開放時長與主色調
- Windows 平台等價實作

## 提案方案

熱鍵註冊與設定管理在 Dart 側，特效播放全程於 macOS 原生層閉環：

| 層級 | 工具 | 負責 |
|------|------|------|
| Flutter 層 | `hotkey_manager` | 全域熱鍵註冊（沿用 `lib/main.dart` 既有模式） |
| Flutter 層 | method channel | 觸發原生播放，傳入時長與主色調 |
| macOS 原生層 | 獨立 `NSWindow` + `CALayer` | 特效視窗建立與 Core Animation 動畫 |
| macOS 原生層 | `CVDisplayLink` | 播放期間逐幀取樣游標位置 |
| UI 層 | 設定面板 | 啟用開關、時長滑桿、色彩選擇 |

### 替代方案

三項技術選型（特效層渲染技術、觸發機制、被排除的連點方案）的完整論證見 SPEC-008「架構決策」，此處不重複。

### 失敗防護

當任一假設不成立時的退路：

- 假設 1 不成立（熱鍵與他人環境衝突）：改換組合鍵，或提前開放熱鍵自訂
- 假設 2 不成立（特效層無法覆蓋全螢幕應用）：接受全螢幕情境不顯示，功能於一般桌面情境仍有效
- 假設 3 不成立（逐幀跟隨造成可感知延遲）：改為觸發當下取樣一次、播放期間不跟隨游標
- 假設 4 不成立（特效視窗搶奪焦點或干擾操作）：檢查 `ignoresMouseEvents` 與視窗 level 設定；必要時改用 `NSPanel` 並設 `nonactivatingPanel`

### 建議方案

採用上述方案。SPEC-008 決策 1 已論證特效層選型不依賴 Flutter 版本演進；決策 2 已論證鍵盤熱鍵是唯一能同時涵蓋滑鼠與觸控板使用者的觸發方式。

## 驗收條件

- [ ] 按下 `Cmd + Option + L`，游標所在螢幕播放定位特效
- [ ] 特效包含聚光燈、邊框閃爍、游標波紋三個組成
- [ ] 游標在非時鐘所在螢幕時，特效正確出現於游標所在螢幕
- [ ] 特效播放期間可繼續操作底下的應用（特效層不攔截滑鼠）
- [ ] 特效播放結束後畫面無殘留
- [ ] 設定面板可停用功能、調整特效時長與主色調，變更即時生效
- [ ] 未取得輔助使用授權時功能仍正常運作
- [ ] 全螢幕播放影片時觸發，特效仍可見
- [ ] 既有功能（透明遮罩、時鐘、滑鼠按鍵綁定、開機啟動）不回歸

## Reality Test / 觸發案例實證

### 觸發案例

開發者在多螢幕環境下工作，切換應用後經常需要花數秒掃視各螢幕尋找游標。此情境每日發生多次。使用觸控板時無側鍵可用，故觸發方式須與指向裝置種類無關。

### 假設列舉

- 假設 1：`Cmd + Option + L` 不與 macOS 系統快捷鍵或常用 app 快捷鍵衝突
- 假設 2：`level = .screenSaver` 的特效視窗可覆蓋假全螢幕應用（影片、簡報、遊戲）
- 假設 3：`CVDisplayLink` 逐幀更新聚光燈圓心不造成可感知延遲
- 假設 4：`ignoresMouseEvents` 的特效視窗不干擾播放期間的既有操作
- 假設 5：`hotkey_manager` 於本專案已移除 App Sandbox 的環境下仍正常註冊系統層級熱鍵

### 實驗驗證

## 風險與權衡

| 風險 | 影響 | 緩解措施 |
|------|------|---------|
| 熱鍵組合與他人環境衝突 | 功能無法觸發 | W1 查證常見衝突；必要時換組合或提前開放自訂 |
| 特效層與時鐘遮罩的視窗層級互相干擾 | 時鐘閃爍或特效被遮蔽 | 兩視窗職責與屬性完全分離，特效視窗獨立建立與釋放 |
| 手需離開指向裝置去按鍵盤 | 使用體感不如原構想的連點觸發 | 已知取捨，經評估後接受（連點方案風險過高，詳 SPEC-008 決策 2） |
| `SettingsModel` schema 升版影響既有使用者 | 設定遺失 | 沿用 SPEC-004 既有容錯模式；v3 資料缺欄補預設，測試涵蓋 round-trip |

## 討論記錄

### 2026-07-29

- 原始構想為 Control + 連點三下，且含「游標本身變換顏色」。後者經確認 macOS 無公開 API 支援，改以疊加特效層達成等效目的
- 曾規劃擴充 SPEC-007 的 `MouseAction` 新增動作型別以重用綁定架構，經用戶指出需支援觸控板而排除——綁定模型以實體側鍵為鍵，觸控板無側鍵可綁
- 已知 `CGEventTap` 可攔截並消費事件，使「修飾鍵 + 連點三下」在技術上可行且觸控板通用；經評估後仍排除，理由為左鍵熱路徑的狀態機風險與收益不成比例
- 確認特效層採 Swift `NSWindow` + `CALayer`，不經 Flutter engine
